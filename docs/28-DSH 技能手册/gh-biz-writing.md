# 商务写作与工作汇报

## 适用场景

- 写周报/月报、项目汇报、工作总结构。
- 写方案、申请、立项材料。
- 向上沟通：要资源、要决策、同步风险。
- 不适用：技术文档（用 `gh-technical-writing`）；行业研究长报告（用 `gh-research-report`）。

## 前置条件

- 明确三件事：**读者是谁**（直属领导/跨部门/高管）、**要什么**（知情/决策/资源）、**看多久**（30 秒还是 10 分钟）。这决定了详略与结构。
- 素材齐全：数据、事实、时间线。

## 步骤

1. **结论先行**：第一段就写清"发生了什么 / 我的建议是什么 / 需要你做什么"。不要从背景铺垫开始。
2. **结构用金字塔**：结论 → 3 个支撑论点 → 每个论点下的证据。同级论点用同一逻辑维度（不能一个说收益、一个说进度、一个说风险）。
3. **汇报三类内容分清楚**：
   - **进展**：完成了什么（用可验证的结果，不是"推进中"）、进度百分比、与原计划的偏差。
   - **问题**：具体问题、影响范围、我已尝试的方案、需要什么支持。**不要只抛问题不给方案**。
   - **计划**：下一步做什么、什么时候完成、依赖谁。
4. **数据说话**："响应时间从 800ms 降到 180ms"优于"性能大幅提升"；"覆盖 3 个部门 47 人"优于"覆盖多个部门"。
5. **方案文档要点**：背景与问题 → 目标与成功标准 → 备选方案对比（含成本、周期、风险）→ 推荐方案与理由 → 需要的资源与决策点 → 风险与应对。
6. **向上沟通**：把决策点前置并给出推荐选项（"建议选 A，因为…"），不要让领导做开放题。
7. **篇幅控制**：一页能说清的不写三页；长文档前面加摘要。

## 常见坑

- 从背景讲起，领导看了三屏还不知道结论。
- 用"基本完成""正在推进""持续优化"这类无法证伪的表述。
- 只报喜不报忧，风险暴露时已无缓冲时间。
- 抛问题不给方案，把决策成本转嫁给上级。
- 方案只给一个选项，没有对比就不是方案是通知。
- 一堆定语和形容词（"高度重视""深入贯彻"），去掉后信息量不变。
- 术语堆砌，读者看不懂等于没沟通。

## 验证

- 第一段就能回答"结论是什么、要我做什么"。
- 所有进展用可验证的结果描述。
- 每个问题都配了应对方案。
- 关键数字准确且有来源。
- 删掉任意一段，读者理解是否受损？不受损的段落就该删。
