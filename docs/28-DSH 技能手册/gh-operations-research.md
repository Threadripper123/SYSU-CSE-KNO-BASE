# 运筹优化与资源调度

## 适用场景

- 有限资源下最大化产出（人力排班、机器排产、预算分配）。
- 路径与配送优化、装箱与切割问题。
- 库存与补货策略、安全库存与服务水平权衡。
- 不适用：单纯的数据统计（用 `gh-numerical-computing`）；无约束的经验判断。

## 前置条件

- 明确三件事：**决策变量**（能调什么）、**目标函数**（最大化/最小化什么）、**约束**（不能违反什么）。缺一个就无法建模。
- 工具：小规模用 `scipy.optimize.linprog`（已装）；整数规划/复杂建模装 `pulp`（`pip install pulp`，本机未装）。
- 先确认问题规模：变量数过万且需精确最优时，要评估求解时间是否可接受。

## 步骤

1. **写数学形式**：把问题翻译成 `max/min c^T x` + `Ax ≤ b` + 变量域。写出来再写代码。
2. **先求松弛解**：线性规划松弛（去掉整数约束）给出目标值的理论上界/下界，用来判断后续方案还有多少优化空间。
3. **整数约束**再引入：用 `pulp`/CBC，给求解时间上限；超时返回当前最优可行解而非崩溃。
4. **灵敏度分析**：报告目标系数与约束右端项的影子价格，指出"放宽哪个约束收益最大"——这往往比最优解本身更有价值。
5. **验证可行性**：把解代回原约束逐条检查（浮点误差可能导致 `Ax ≤ b` 差一点点越界，需设容差）。
6. **对比基线**：与当前人工方案比较，给出改进幅度（成本降 X%、产出升 Y%）。
7. 输出：模型假设、目标值、关键约束的实际使用率、可落地的调度表。

## 常见坑

- 约束写漏导致解"数学上最优、现实中不可行"（如忽略了换班间隔、最短休息时间）。
- 目标函数用绝对值或非线性项直接进 LP，报错；需线性化（引入辅助变量）。
- 整数变量数爆炸导致求解几小时无结果，应先聚合粒度或改用启发式（贪心+局部搜索）。
- 浮点比较 `if x > 0` 因 `1e-16` 残差误判，需用容差。
- 只给最优解不给灵敏度，业务方不敢用（"把预算加 10% 会怎样"答不上来）。
- 忽略调整成本：方案理论最优但需要重排全部班组，实际落地成本高于收益。

## 验证

- 解逐条满足全部约束（给出代入检查结果）。
- 目标值不劣于基线，且改进幅度可解释。
- 给灵敏度结论与至少一条"若要进一步提升需放宽什么"。
- 大规模问题报告求解耗时与 gap。
