# 自动化工作流编排

## 适用场景

- 同一套操作每天/每周重复（同步、汇总、清理、巡检）。
- 多步骤任务需要串起来：取数 → 处理 → 校验 → 通知。
- 长任务需要断点续跑、失败重试、进度可见。
- 不适用：一次性手工操作；纯网页操作（用 `conn-web-automation`）。

## 前置条件

- 明确触发方式：手动、定时（cron/计划任务）、事件驱动。
- 明确幂等要求：重复执行是否会重复写入/重复发送。
- 本机 Windows 环境；跨平台脚本注意路径与命令差异。

## 步骤

1. **画清楚步骤图**：每步的输入、输出、失败处理写成一列，标出哪些步骤可并行。
2. **状态外置**：进度与已处理标记写入文件或数据库（如 `state.json` 记录已完成项与时间戳），进程重启后能跳过已完成部分。不要只靠内存变量。
3. **幂等设计**：写操作前先查是否存在；批量发送前用去重键（`hash(内容)`）。重复跑一遍不应产生副作用。
4. **失败分类**：可重试（网络超时、锁冲突）与不可重试（参数错误、权限不足）分开处理；重试用指数退避并设上限。
5. **可观测**：结构化日志（时间、步骤、对象 id、结果），以及一份人类可读的总结（处理数、跳过数、失败项清单）。
6. **定时化**：Windows 用 `schtasks /create`，Linux 用 crontab；写清时区与错过执行的补偿策略。
7. **交付**：给出完整命令序列、日志位置、手动重跑方式与回滚方法。

## 常见坑

- `while True` 无退出的守护循环吃掉 CPU：设置间隔与最大轮次，优先事件驱动或系统调度。
- 状态文件与锁文件放在云同步目录（如网盘同步盘），被同步客户端长时间占用导致写失败；应放本地非同步路径。
- 时间比较未统一时区，跨日任务判定错乱。
- 忘记处理空输入：上游返回 0 条时脚本崩溃或误把空当成功。
- 并发写同一资源没有锁，导致重复处理。
- 只写"什么样的做法"不写"失败了怎么办"。

## 验证

- 中断后重跑，不产生重复结果（幂等实测）。
- 模拟一次网络失败，确认重试与降级路径生效。
- 空输入、单条输入、超大输入三档各跑一次（边界与批量规模）。
