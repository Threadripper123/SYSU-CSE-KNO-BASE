# 元宝桌面真实对话

## 前置条件

- 用户明确授权向元宝发送指定任务内容；不擅自发送其他私人材料。
- Windows PowerShell可用，元宝已登录；不自动处理账号密码或登录验证。
- 操作会切换前台并使用剪贴板，开始前向用户说明。

## 步骤

1. 用Get-Process查元宝MainWindowHandle与进程ID，用UIAutomationClient的AutomationElement.FromHandle获取窗口树。
2. 用WScript.Shell的AppActivate将元宝切到前台，再用System.Drawing.Bitmap、Graphics.CopyFromScreen截屏，以read_image查看。截图只证明被截区域当前可见的内容，不是后台窗口截图。
3. 必须依实际截图或控件BoundingRectangle确定输入框和按钮位置，不复用历史绝对坐标。截图若与预期窗口不符，停止点击并重新定位。
4. 提问内容先写入UTF-8文本并Set-Clipboard。SendKeys快捷键可能失效而误发字母v；已验证可用user32.keybd_event显式按下与释放Ctrl和V，先释放Ctrl/Shift/Alt，再Ctrl+A替换输入。发送前读取FocusedElement的TextPattern.DocumentRange.GetText(-1)或截图确认完整问题，随后定位并点击发送按钮。延续研究使用当前对话，新任务才新建。
5. UIAutomation树初次可能只有Pane，激活并等待页面渲染后可出现正文、按钮和分组。不要因此直接判定不可操作。
6. 以是否存在Name为“停止回答”的控件辅助判断生成状态，同时检查回答末尾。生成时准备下一轮问题或整理材料，不密集轮询。
7. 回答完成后，在控件树找Name为“复制”的回答操作。已验证该Group支持InvokePattern，可直接调用Invoke后读取剪贴板，即使按钮Bounds在视口外也可成功；按对话顺序选目标回答（不是代码复制）。不支持Invoke时才滚动到可见位置再点击。保存完整原文。
8. 读回保存文件，确认不是提问文本或旧剪贴板，再继续下一轮。原文与助手校对意见分别存放。
9. 保存当前任务所需内容，不把历史会话侧栏标题导出到最终交付。截图若含其他私人信息，优先改为窗口或回答区域截图。

## 常见坑

- CopyFromScreen截的是前台桌面，目标应用被遮挡时会截到其他应用。必须先激活再截图。
- 文本控件Name逐项导出会把代码拆成碎片；适合作为临时诊断，不如回答“复制”按钮获得的完整原文。
- 某些工具传递Windows反斜杠路径时出现丢失分隔符；文件工具优先工作区相对路径，PowerShell字符串优先正斜杠绝对路径，并验证实际生成位置。
- 复制按钮可能有多处，区分代码复制、用户消息复制、回答复制和分享；用控件树及截图确认。
- 模型给出的链接与事实仍需核验。内部staging域名、拼写错误和版本差异要单列，不默默改写原文冒充模型已修正。

## 验证

- 界面存在实际发送的问题和回答。
- 保存的回答内容与当前问答主题一致，正文和代码不是控件碎片。
- 多轮任务记录提问顺序、原文与未核验事项，不声称已完成未执行的实验。
