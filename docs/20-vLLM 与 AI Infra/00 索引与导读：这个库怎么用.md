## 这个库是什么
本库是一次联网采集 + 中文结构化重写的成果，主题覆盖三条主线：
1. **vLLM 与 LLM 推理系统**：调度、KV Cache 管理、连续批处理、前缀缓存、投机解码、量化、分布式部署。

3. **CUDA / Triton 算子**：执行模型、内存层次、GEMM 与 Attention 算子的优化路径、性能分析工具。

库内文档分两类：
- **编号文档（00–10、99）**：中文综述，带结论、表格与可执行参数，适合直接阅读和学习。
- **原始抓取文档**：官方文档、论文、博客的正文原文（标题即来源主题），适合核对细节与引用原文。

## 核心术语速查
- **Prefill / Decode**：prefill 一次并行处理整段 prompt（compute-bound）；decode 每步只算 1 个 token（memory-bound）。两者特征完全不同，这是绝大多数推理优化的出发点。
- **TTFT / ITL / TPOT**：首 token 延迟 / 相邻 token 间隔 / 平均每 token 时间。批处理几乎总在拿 ITL 换吞吐。
- **KV Cache**：缓存每层注意力的 K、V，避免重复计算；其显存占用随 batch × 序列长度线性增长，是长上下文服务的头号瓶颈。
- **Block / Page**：KV cache 的固定大小分配单元（vLLM 默认 16 个 token），类比操作系统分页。
- **Continuous Batching**：以 iteration 为粒度动态增删请求，而不是等整批跑完。
- **Arithmetic Intensity**：每字节内存流量对应的浮点运算数，决定 kernel 是 compute-bound 还是 memory-bound。
