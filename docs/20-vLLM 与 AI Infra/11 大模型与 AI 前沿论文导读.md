# 11 大模型与 AI 前沿论文导读

> 主题库：vLLM 与 AI Infra　｜　源文件：（纯文本条目）　｜　3,646 字符　｜　8 个片段　｜　更新于 2026-11-13
本库已收录 34 篇论文原文（arxiv 抓取，标题以「论文·」开头）。本文是导读：按主题分组，给出**一句话结论 + 为什么值得读**，方便按需深挖。

## A. 基础架构：注意力之外还有什么
| 论文 | 一句话结论 | 为什么重要 |
|---|---|---|
| Attention Is All You Need (1706.03762) | 纯注意力堆叠即可超越 RNN/CNN，训练可完全并行 | 当前一切 LLM 的原点；读它对理解 KV cache、位置编码、多头切分是刚需 |
| ViT (2010.11929) | 图像切成 16×16 的 patch 当 token，数据足够时击败 CNN | 多模态模型视觉编码器的默认起点 |
| DDPM (2006.11239) | 学习「逐步去噪」比一次性生成容易得多 | 扩散模型的理论基石；如今与自回归语言模型在图像/视频上正面竞争 |
| Mamba (2312.00752) | 选择性状态空间模型，序列长度线性复杂度，同尺寸吞吐可达 Transformer 数倍 | 长序列场景绕开 O(N²) 注意力的主流替代路线 |
| Mamba-2 (2405.21060) | 用「状态空间对偶」把 SSM 与注意力统一，训练比 Mamba 快数倍 | 说明 SSM 不是旁支，而是与注意力同一家族的另一端 |
| Chameleon (2405.09818) | 早期融合：文本与图像都变成 token，用一个 Transformer 统一建模 | 混合模态（any-to-any）模型的代表性架构 |
| Titans (2501.00663) | 引入可在推理时更新的神经长期记忆，上下文可推到百万级 | 「记忆」作为独立模块的方向，与 RAG、长上下文注意力互补 |

## B. 缩放律与训练：钱花在哪
| 论文 | 一句话结论 | 为什么重要 |
|---|---|---|
| Scaling Laws (2001.08361) | 损失随参数量/数据量/算力呈幂律下降 | 所有「该训多大」决策的起点 |
| Chinchilla (2203.15556) | 计算最优时每参数约 20 个 token，当时的大模型普遍训练不足 | 直接改写了业界的数据配比；今天「过训练小模型」是刻意的推理成本优化 |
| GPT-4 (2303.08774) | 多模态、可预测的缩放，但架构与数据细节未公开 | 读它是为了理解「技术报告可以隐藏什么」，别指望复现 |
| Llama 3 (2407.21783) | 15T token、405B 参数、GQA + 128K 词表，开源权重里最强的工程报告 | 少见的完整训练配方：数据清洗、并行策略、评测方法 |
| DeepSeek-V2 (2405.04434) | MLA 把 KV cache 压缩 90%+，DeepSeekMoE 用细粒度专家 + 共享专家 | 中文团队最重要的架构创新之一，直接决定长上下文推理成本 |
| DeepSeek-V3 (2412.19437) | 671B 总参 / 37B 激活，FP8 训练 + 无辅助损失负载均衡 + 多 token 预测 | 目前最完整的「大规模 MoE 训练工程」公开报告 |
| Mixtral (2401.04088) | 8×7B、top-2 路由，46.7B 总参只激活 12.9B | 稀疏 MoE 在开源界的普及之作 |
| BitNet b1.58 (2402.17764) | 权重取 {-1,0,1}，3B 以上规模可追平 FP16 质量 | 极端量化路线的可行性证明，硬件协同设计的风向标 |

## C. 对齐与推理能力：从「会说话」到「会想」
| 论文 | 一句话结论 | 为什么重要 |
|---|---|---|
| DPO (2305.18290) | 把 RLHF 的目标函数化简成分类损失，不需要奖励模型和在线采样 | 如今微调对齐的默认选择，工程成本极低 |
| Chain-of-Thought (2201.11903) | 让模型写出中间步骤，推理准确率随规模大幅提升 | 「推理」能力的第一个可操作杠杆 |
| ReAct (2210.03629) | 推理与行动交替：想一步、调一次工具、再想 | 所有 Agent 框架的原型 |
| Tree of Thoughts (2305.10601) | 把思考组织成树，支持前瞻与回溯 | 推理时搜索的早期形态，与今天的 test-time scaling 一脉相承 |
| Toolformer (2302.04761) | 模型自监督地学会何时调用哪个 API | 工具调用的起点 |
| DeepSeek-R1 (2501.12948) | 纯强化学习（GRPO + 规则奖励）即可涌现长链推理；蒸馏到小模型同样有效 | 目前公开的最完整「推理模型」训练报告 |
| Test-time compute (2408.03314) | 小模型 + 更多推理时算力，可胜过更大的模型 | 改变了 scaling 的方向：算力不只用在前向，也用在对齐搜索与验证 |

## D. 推理系统与算子：把 FLOPs 变成 token/s
| 论文 | 一句话结论 | 为什么重要 |
|---|---|---|
| PagedAttention / vLLM (2309.06180) | 用分页管理 KV，显存浪费从 60–80% 降到 4% 以下，吞吐提升 2–4× | 本库 01/02 的理论来源 |
| FlashAttention (2205.14135) | 分块 + online softmax，不物化 N×N，IO 大幅下降 | 长上下文可行的前提 |
| FlashAttention-2 (2307.08691) | 重排工作划分、减少非 matmul FLOPs，约 2× 提速 | 目前多数框架的默认 attention 后端 |
| FlashAttention-3 (2407.08608) | 用 Hopper 的 TMA/wgmma 异步流水 + FP8，再提 1.5–2× | 展示「算子要吃透硬件代际」的范例 |
| SGLang (2312.07104) | RadixAttention 用基数树复用前缀，配合前端 DSL | 多轮对话/结构化生成场景的重要对手 |
| Speculative decoding (2211.17192) | 小模型猜 k 个 token，大模型一次验证，输出分布不变 | 无损加速的标准做法 |
| EAGLE (2401.15077) | 在特征层做草稿而非 token 层，接受率显著更高 | 当前投机解码的主力方案之一 |
| Ring Attention (2310.01889) | 分块注意力 + 通信与计算重叠，环形传递 KV | 超长上下文训练的关键技术 |

## E. 压缩与适配：用更少的显存跑同样的模型
| 论文 | 一句话结论 | 为什么重要 |
|---|---|---|
| GPTQ (2210.17323) | 逐层二阶误差补偿，4-bit 权重量化几乎不掉点 | W4A16 的两大主流之一 |
| AWQ (2306.00978) | 按激活幅度保护约 1% 的显著通道，4-bit 优于 GPTQ 且更鲁棒 | 工程上更省事，免反向传播 |
| SmoothQuant (2211.10438) | 把激活的量化难度按通道转移到权重，实现 W8A8 | 激活量化的关键技巧 |
| LoRA (2106.09685) | 冻结原权重，只训练低秩增量，参数减少数个数量级 | 微调的事实标准 |

## 阅读建议
1. **只读 5 篇**：Attention Is All You Need → Chinchilla → PagedAttention → FlashAttention → DeepSeek-V3。这五篇覆盖了「模型怎么来、算力怎么配、推理怎么快、工程怎么做」。
2. **做推理系统**：D 组全读，配合本库 01/02/06/10。
3. **做训练/对齐**：B + C 组，重点 DPO 与 DeepSeek-R1。
4. **做端侧/成本敏感**：E 组 + BitNet + Mamba 系列。
