# MC-23 客户端性能优化 2025–2026：Sodium 0.6、Iris、Nvidium、ImmediatelyFast、EntityCulling

## 一句话结论

客户端优化的决策维度已经从"装不装 Sodium"变成两个：**你的 MC 版本落在哪条 Sodium 分支上**，以及**你的显卡配哪个渲染后端**。Sodium 在不到两年里从 0.6 走到 0.9，每一代都锁死一段 MC 版本区间；同时 1.21.11 与 26.3 在 2026 年下半年各有一条仍在更新的线（`0.8.15-beta.1` 与 `0.9.3-beta.5`）。装错分支的表现不是崩溃，而是"看起来装上了、帧数没动"。

## Sodium：四个台阶与两条并行分支

**0.6 是 1.21.4/1.21.5 时代的收尾线。** 它从 0.6.2 一路补到 0.6.13，跨了 1.21.4 与 1.21.5 两个 MC 小版本。这一段的意义不在新功能，而在"末版对齐"：0.6.13 同时是 1.21.4 与 1.21.5 的最后版本，说明 Sodium 团队在这个节点上把小版本差异压进了同一份产物。

**0.7 是短命的一代，只服务 1.21.9/1.21.10。** 从 2025-09-30 的 `0.7.0` 到 2025-11-10 的 `0.7.3`，总共四十天。这恰好对应 MC 1.21.9 与 1.21.10 之间的短周期。判断方法很简单：如果你的实例是 1.21.9，看到 0.8.x 不要装，看到 0.7.x 才是对的。

**0.8 是跨度最大的一代，横跨 1.21.1 到 26.1。** 26.1 首发时是 `0.8.7`（2026-03-24），十天后再推 `0.8.9`；与此同时 1.21.1 这条老线在 2026-08-28 还收到了 `0.8.13`。这说明 0.8 被当成"长期支持"分支维护，1.21.1 这种两年多前的版本仍有人管。对整合包作者来说，0.8 是 2026 年里最安全的选择。

**0.9 从 26.2 开始，当前仍在 beta。** 26.2 的 `0.9.2` 于 2026-09-11 转正，26.3 的 `0.9.3` 从 2026-10-15 的 beta.1 迭代到 2026-11-12 的 beta.5，一个月内推了五个 beta。看 release 内容能判断这个阶段在修什么：Intel 核显画面异常、非满块的流体剔除、macOS 全屏菜单可见性、倒置方块（falling blocks）异常、F3 界面反复重建资源导致的内存泄漏。全是边角料，没有管线级改动。

**两条并行分支是 2026 年最容易被忽略的事实。** 2026-09-20 同一天，Sodium 既发了 26.3 的 `0.9.3-alpha.1`，也发了 1.21.11 的 `0.8.15-beta.1`。一个团队同时维护两条版本线，意味着 bug 修复不一定回移：你在 1.21.11 上等的那个修复，可能只在 26.3 线存在。

## Iris：配对纪律比功能更重要

Iris 的版本号跟 MC 走，不跟 Sodium 走，所以两者必须按表配对。已知的配对点是：

- `1.8.3+1.21.4`（2024-12-04）到 `1.8.8+1.21.4`（2025-02-20），对应 Sodium 0.6 线。
- `1.9.2+1.21.9`（2025-09-30）到 `1.9.7+1.21.10`（2025-12-18），对应 Sodium 0.7 线。
- `1.10.9+26.1`（2026-04-03），对应 Sodium 0.8 线。
- `1.11.2+26.1`（2026-07-09）到 `1.11.7+26.3`（2026-09-30）。

还有一个必须记住的事故：Sodium 在 2026-09-15 发布 26.3 的 `0.9.2` 时，release 说明里直接写了 "Iris is not yet compatible. If you want to use Iris, don't update Sodium until Iris receives an update."。Iris 的 26.3 版本 `1.11.7+26.3` 到 2026-09-30 才出现，中间空了十五天。**光影玩家在 MC 大版本刚发布的头两周，最稳的策略是"等 Iris，别等 Sodium"**，因为 Sodium 会抢先适配，Iris 要跟在后面。

另一个观察：1.21.9/1.21.10 的 Iris 版本行里只列了 Fabric 构建，NeoForge 构建是否同期发布需要在你自己的实例里确认，不能从版本列表直接推断。

## Nvidium：门槛写在硬件上

Nvidium 是用 NVIDIA 专属 OpenGL 扩展做的 Sodium 后端替换，官方说明写得很直白：**必须支持 mesh shaders 的 NVIDIA 显卡**，该特性从 Turing 架构开始，也就是 GTX 16 系与 RTX 20 系及以后。非 N 卡上它会**自动禁用自己**，游戏不受影响，但也不会有任何提升。

这个"自动禁用"设计很聪明，也很容易骗人：装了、没崩、帧数没变，用户会以为 Nvidium 没用，其实是硬件不满足。当前版本 `0.4.4-beta7-26.3`（2026-09-23）仍带 beta 标记，从 2026-08-29 的 beta5 到现在也就几个 beta 的跨度，说明这条线是"跟版本适配"而非"功能开发"。

用不用它，判断很简单：N 卡 20 系以上、追求极限帧数、能接受 beta 的偶发画面问题，就装；A 卡、Intel 核显、或给整合包做默认配置，就不要装——它在你的用户群里对一半人无效，却增加一个兼容面。

## 配角们：ImmediatelyFast、EntityCulling 与一批"看不见"的优化

**ImmediatelyFast** 优化的是即时渲染路径：HUD、文本、实体、粒子里的重复批处理。它的版本线和 MC 分支绑得很死：26.3 线是 `1.17.1+26.3`（2026-09-17），而 1.21.1 线仍停在 `1.6.15+1.21.1`（2026-10-13）。同一时间两个大版本号并存，说明它对老 MC 分支是冻结式维护——只修崩溃，不加功能。

**EntityCulling** 做的是遮挡剔除：被墙挡住的实体不去走着色器绘制。它的版本号 `1.12.1` 在 26.2 与 26.3 上通用，2026-11-13 发布，是本文里最新的一次更新。这类优化在大型整合包（几百个实体、密集刷怪场）里收益最明显，在空旷原版生存里几乎测不出来。

**还有一批模组不显眼但值得装**：Lithium（`mc26.3-0.26.3`，2026-10-28，通用逻辑优化）、FerriteCore（`9.0.0`，2026-03-24，内存占用）、Krypton（`0.3.2`，2026-09-30，网络栈）、C2ME（`0.4.2-alpha.0.119+26.3`，2026-11-12，区块并行生成，仍是 alpha）、ModernFix（`5.27.27+mc26.1.2`，2026-11-06，启动与内存）。C2ME 的 alpha 标记要当真：它改的是世界生成线程模型，与部分结构模组冲突的概率不低。

**Forge 生态要单独说。** Sodium 从 0.6 起在 Modrinth 上同时提供 ⟦fabric⟧ 与 ⟦neoforge⟧ 构建（版本列表里两者成对出现），所以 NeoForge 用户可以直接用官方 Sodium。更老的 Forge 版本（1.20.1 及以前）没有官方构建，长期依赖社区分支，这些分支当前的维护状态本文没有核实，选包时务必看它最近一次更新时间。

**spark** 也能装在客户端（`1.10.187`，2026-09-19）。客户端卡顿排查用 `/spark profiler start`，比凭感觉关设置靠谱。

## 怎么验证优化真的生效

客户端优化最容易自欺：装完感觉快了，其实只是换了视角。想拿到可比的数据，先把变量摁住。

**固定测试场景。** 同一个存档、同一组坐标、同一个朝向与视距，最好录一段固定路线的回放。测试时关掉 VSync，并把帧率上限拉到 ⟦260⟧ 或直接 ⟦Unlimited⟧——VSync 会把所有高于刷新率的改善全部吃掉，这是"装了没感觉"的头号原因。

**看帧时间，不看平均帧数。** F3 里真正有用的是帧时间曲线与最低帧，不是左上角那个平均值。Sodium 这类管线优化改善的是均值，EntityCulling 改善的是尖峰（大量被遮挡实体同时进入视锥时的那几十毫秒）。只测平均 fps，会把 EntityCulling 的收益测成零。

**一次只改一个变量。** Sodium → Iris → ImmediatelyFast → EntityCulling 逐层加，每层记录一次。四五个模组一起装完再对比，出问题时无法定位是谁。

**需要归因时用 spark。** 客户端装 spark（⟦1.10.187⟧）后执行 ⟦/spark profiler start⟧，采样一段时间再 ⟦/spark profiler stop⟧，它会给出火焰图。渲染线程热点和主线程热点要分开看：前者指向 Sodium/Iris，后者多半是实体或区块逻辑。

**别忽略运行时底座。** 26.1 起 MC 最低要求 Java SE 25，用旧 JDK 启动会在类加载阶段就出问题，表现成"模组装了但游戏起不来"；显卡驱动同理，Sodium 的现代管线对驱动版本比原版敏感。

## 安装顺序与实例配置

顺序错了会出现很难查的软故障，按下面这条链走基本不会错：

1. 加载器（Fabric Loader 或 NeoForge）与对应 API；
2. Sodium——先让它跑通，确认帧数基线；
3. Iris（只有需要光影时）——版本必须与 Sodium 主版本配对；
4. ImmediatelyFast、EntityCulling——纯增益，出问题好摘；
5. Lithium、FerriteCore、Krypton——改逻辑/内存/网络，冲突面稍大；
6. C2ME、ModernFix 这类改动较深的，最后加，出问题第一个摘。

**内存给多少。** 客户端 ⟦-Xmx4G⟧ 起步，大型整合包 6–8G 足够。给到 12G 以上对客户端几乎没有收益，反而拉长单次 GC 停顿，表现为"每隔几十秒卡一下"——这种卡顿最容易被误判成模组冲突。

**实例要隔离。** Prism Launcher、Modrinth App 都是每个实例一份独立的 ⟦mods⟧ 目录，不要为了省空间做目录软链共用：两个实例对 Sodium 版本的要求经常不一样，共用目录等于把两套依赖强行合并。

**版本要写死。** 整合包在 ⟦pack.toml⟧ 或任务书里把 MC 版本与加载器版本写成固定值，不要留"最新"。Sodium 0.8 与 0.9 之间是整代差距，浮动版本约束会把用户推到不兼容的组合上。

## 对不同角色的实际影响

**普通玩家**：先确认 MC 版本，再按配对表装 Sodium + Iris，最后按显卡决定 Nvidium。不要"全都装"——Nvidium 与部分光影包的后端假设冲突，出问题的概率高于收益。

**整合包作者**：在 `packwiz` 或任务书里锁死具体版本号，不要用"最新版"这种浮动约束。Sodium 0.8.13 与 0.9.2 之间隔着一整代渲染管线，用户在 1.21.1 世界里装到 0.9 的包，症状是启动即崩或方块全黑。Modrinth 的版本接口可以按 `game_versions` 过滤，CI 里做一次校验能省很多支持工单。

**服务端/CI**：客户端模组不影响专用服务器，但整合包分发时要把 `mods` 目录按 `client-only` 标记过滤。Sodium、Iris、Nvidium、ImmediatelyFast 都是纯客户端，EntityCulling 有服务端侧组件，混装会导致服务器启动报错。

## 常见坑

1. **拿 0.9.x 去配 1.21.11**。1.21.11 的线是 0.8.15-beta.1，0.9 只服务 26.2/26.3。
2. **Sodium 更新早于 Iris**。大版本发布头两周，Sodium 转正而 Iris 没跟上，光影直接不可用；等 Iris 再升 Sodium。
3. **在 A 卡上装 Nvidium**。它会自动禁用，帧数不动，白折腾；看日志或直接不装。
4. **把 0.6.13 当成"通用末版"**。它只覆盖 1.21.4/1.21.5，1.21.1 要的是 0.8.13。
5. **ImmediatelyFast 版本号看花眼**。`1.17.1` 是 26.3 线，`1.6.15` 是 1.21.1 线，数字大小不代表新旧。
6. **C2ME 当稳定模组用**。它到 2026-11 仍是 alpha，与世界生成类模组冲突时优先摘它。
