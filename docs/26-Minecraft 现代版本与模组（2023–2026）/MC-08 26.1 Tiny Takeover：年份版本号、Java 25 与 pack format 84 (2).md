# 26.1 Tiny Takeover：年份版本号、Java 25 与 pack format 84

> 资料截至 2026-11-15；覆盖 2023-11 至 2026-11，重点 2024–2026。

## 一句话结论

26.1「Tiny Takeover」对外宣传的是"幼年生物变可爱"，但真正改变生态的是三条基建线同时落地：版本号体系从 `1.21.x` 切成年份前缀 `26.x`、运行环境抬到 Java SE 25 并重写默认 JVM 参数、资源包与数据包格式跳到 `84.0` / `101.1`。它是 2026 年四个 drop 里内容量最小的一作，却是对加载器、整合包、服务器与材质作者破坏面最大的一作。

## 版本号为什么改成 26.x

从 1.20 到 1.21.11，Minecraft 走的是"大版本 + 小版本"的旧命名：`1.21` 是主更新，`1.21.4`、`1.21.9` 这类是 drop 或补丁。2026 年起官方把年份直接写进版本号，`26.1` 读作"2026 年第 1 个 drop"，季度节奏因此变得可预测：一年三到四个 drop，每个 drop 之间是两到三个月的快照期。

对实务的影响有两层。第一层是**文本检索**：教程、整合包说明、模组兼容表里同时存在 `1.21.9`、`1.21.11`、`26.1` 三种写法，搜索"1.21.10"可能什么都找不到，因为该版本不存在。第二层是**兼容性判断**：`26.1` 与 `1.21.11` 之间是断代，不是小版本号顺延，任何写着"支持 1.21.x"的模组默认都不支持 26.1，必须看它有没有单独发 26.1 构建。

开发期代号也值得记一笔：26.1 在开发阶段被称作 `Drop 1 of 2026`，Bedrock 的实验性开关同名；正式名 Tiny Takeover 在 2026-03-21 的 Minecraft LIVE 上公布，三天后发布。这类"先公布名字、再发版"的节奏在 26.2 与 26.3 上重复出现。

## Java 25：这次为什么躲不过去

26.1 把最低 Java 从 21 抬到 **Java SE 25**，并且把内置发行版换成 **Microsoft Build of OpenJDK 25**。这不是"建议升级"，而是启动器层面的硬门槛：用 Java 21 启动 26.1 会直接拒绝启动。

随之改动的是默认 JVM 参数，这一块比 Java 版本更容易被忽略：

- 默认最大堆从 **2 GB 提到 4 GB**。原版客户端 4 GB 已经很宽裕，但整合包作者要注意：启动器给的默认值变了，玩家机器上的实际表现也会变。
- 垃圾回收从 **G1GC 改为 ZGC**（仅限兼容的硬件与系统，wiki 自己在这一条上标了"需要更多信息"）。ZGC 的卖点是低停顿，代价是更高的内存与 CPU 开销，以及需要较新的 JDK 与操作系统配合。
- 默认参数追加 `-XX:+UseCompactObjectHeaders`、`-XX:+AlwaysPreTouch`、`-XX:+UseStringDeduplication`。前者压缩对象头、降低堆占用；`AlwaysPreTouch` 在启动时预触碰堆页，换来运行期更少的缺页；后者做字符串去重，对大量重复文本（任务书、配方名）有帮助。
- 游戏**不再支持显存 512 MB 及以下的 GPU**。

对整合包与服务器来说，这套默认值的意义是"官方开始替你做调优"。但你自己的启动脚本如果把 `-XX:+UseG1GC` 写死了，就会和新的默认值打架，出现"参数冲突"或干脆没用上 ZGC —— 排查时先看启动器日志里生效的 GC 名称。

## 内容侧：幼年生物、金蒲公英与命名牌

26.1 的主题是"可爱与情感连接"，落到机制上其实只有三件小事，但每一件都改动了长期数值。

**幼年生物全面重做。** 除幼年鹦鹉螺与 ghastling 外，所有幼年生物都换了模型与贴图，碰撞箱按新模型微调；猫、鸡、马、猪、狼新增幼年音效；幼年猪、骆驼、狼不再渲染鞍与盔甲；幼年村民与幼年僵尸村民改成"基础模型 + 各职业 overlay"的结构。最后这条对材质作者是硬变更：原来每个职业一张幼年贴图，现在要按 overlay 拆。

**金蒲公英（Golden Dandelion）。** 配方是 1 朵蒲公英 + 8 个金粒，也能从流浪商人处买到。对幼年生物使用会写入 NBT `AgeLocked=1`，停止生长；再用一次写回 `0`，继续长大。粒子方向区分状态：停止时绿色粒子向下，恢复时向上。它对怪物（含亡灵坐骑，幼年疣猪兽除外）与村民无效，可以盆栽，也能合成黄色染料与饱和效果的迷之炖菜。

对牧场与自动化来说这是新玩具：`AgeLocked` 是实体 NBT 字段，意味着一台机器可以批量把幼年动物"冻龄"成装饰或展示用，而不必担心它们长大。反过来说，任何按"幼年→成年"计时设计的刷怪/繁殖农场，都要考虑玩家会给幼崽上锁。

**命名牌改成可合成。** 1 张纸 + 1 个金粒。同时交易表也改了：大师级图书管理员不再卖命名牌，改为 3 绿宝石卖红色/黄色蜡烛；流浪商人以 1 绿宝石卖命名牌；大师图书管理员保留 3 个交易位，保证在开启"村民交易重平衡"实验时一定刷得出附魔书。命名牌从"结构战利品/钓鱼"变成"可再生"，直接影响空岛与超平坦整合包的早期进度。

## 系统侧：世界时钟、数据驱动交易、植被 tag

这三块是 26.1 对数据包作者最实质的改动，也是后续 26.2–26.4 继续加码的方向。

**世界时钟（world clock）与时间线（timeline）。** 原来"一天 24000 tick"是写死的世界属性，26.1 把它抽象成时钟注册表：`data/<namespace>/world_clock/<id>.json`，内容是一个空对象。每个维度可以挂不同时钟，注册了 `minecraft:the_end` 时钟来驱动末地闪。`/time` 命令随之重写：

- `/time [of <clock>] set <time>`：设置时钟累计 tick；
- `/time [of <clock>] set <timemarker>`：推进到下一个时间标记（主世界有 `day`、`noon`、`night`、`midnight`）；
- `/time [of <clock>] pause` / `resume`：暂停与恢复；
- `/time [of <clock>] query <timeline>`、`query repetition`、`query time`：查相位、查周期重复次数、查累计 tick；
- `/time [of <clock>] rate <rate>`：速率倍率，取值 `0`（不含）到 `1000`（含），只改时钟推进速度，不影响游戏刻模拟。

注意 `/time query gametime` 仍然是"世界总 tick"，不受时钟改动影响；而 `/time set`、`/time add` 通过 `execute store` 返回的值，语义从"当前时刻"变成了"时钟累计 tick"。任何用返回值做算术的命令方块装置都要重算。

**数据驱动村民交易。** 交易从硬编码变成注册表：`data/<ns>/villager_trade/<id>.json` 描述"交易蓝图"，由村民与流浪商人实例化成实际交易；配合 `trade sets`、`villager_trade` 标签与 `minecraft:additional_trade_cost` 组件（临时修改交易要价，交易生成后移除）。新增 `minecraft:dye` 组件表达"任意染料颜色"，替代过去"必须是某个具体染料物品"的写法。对整合包而言，这意味着改交易不必再靠 KubeJS/CraftTweaker 打补丁，纯数据包就能重排经济。

**植被 tag 大重构。** 26.1 引入一整套 `#supports_*` 标签（`#supports_vegetation`、`#supports_crops`、`#supports_stem_crops`、`#supports_sugar_cane`、`#supports_cactus`、`#supports_chorus_plant` 等 30 余个），把"什么方块能托住什么植物"从代码判断变成标签数据。同时 `#dirt` 被拆细：`#dirt` 只剩泥土/粗泥/缠根泥土，新增 `#mud`、`#moss_blocks`、`#grass_blocks`，再用 `#substrate_overworld` 汇总。旧数据包若直接改 `#dirt` 来影响世界生成，升级后会静默失效。

## 渲染与 pack format 84

26.1 的渲染改动集中在"透明怎么画"这一件事上：

- 任意方块模型现在都能使用 cutout 或 translucent 贴图，**具体走哪个 pass 由贴图 sprite 的像素内容决定**：含半透像素的进 translucent，含全透像素的进 cutout，其余进 solid。
- `textures` 映射格式扩展：除原来的内联 sprite ID 字符串，还可以写成对象 `{sprite, force_translucent}`；非字符串条目不再被当作字符串解释，而是直接拒绝。
- 区块几何数据在显存中的存储方式与渲染路径被重写。
- Shader 合并：`core/rendertype_item_entity_translucent_cull` 并入 `core/entity`，`core/rendertype_translucent_moving_block` 并入 `core/block`，`rendertype_entity_alpha`/`rendertype_entity_decal` 改成 `DISSOLVE` 标志；物品渲染从 `core/entity` 拆出独立的 `core/item`。

资源包格式因此定为 **84.0**，数据包格式 **101.1**。这两个数字是判断"旧包能不能直接用"的唯一硬指标：`pack.mcmeta` 里写 `pack_format: 75` 的材质包在 26.1 会提示不兼容，即使它只是换了几张图。

## 26.1 刻意没做的事

把 26.1 放在 2026 全年看，它的定位很清楚：**只做基建，不做地貌**。整个 drop 没有新生物群系、没有新结构、没有新维度，新增方块只有金蒲公英一种。这与 26.2 的硫磺洞穴、26.3 的白杨林、26.4 的冰洞穴形成分工：26.1 先把 Java 25、新渲染管线、新数据格式这三块地基铺好，后面三个 drop 的新内容全部长在这套地基上。

这类"基建 drop"的代价是当季口碑：玩家看到的是"只更新了幼年动物"，但服务器管理员与整合包作者要面对的是 JDK 换代、GC 换代、pack format 换代。判断一个 drop 值不值得升级，不能只看内容清单，要看它的"外围破坏面"。

聊天与运维侧也顺手改了：聊天界面在设置限制下仍可打开（限制说明显示在聊天框顶部与输入框上方，世界设置里也能看到），客户端行为产生的聊天条目（如截图提示）在消息被限制时仍然显示；专用服务器磁盘空间不足时会向 OP 弹 toast；F3 新增 `detailed_memory` 条目，用于排查内存问题。这些改动单看都很小，但都是"服务器出问题时先看哪里"的路径变更。

## 对玩家、整合包与开发者的实际影响

**玩家。** 升级后第一感受是内存占用变高（默认 4 GB + ZGC），低配机器反而可能更卡；第二感受是幼年动物"长得不一样了"，旧存档里的幼崽会直接套新模型。命名牌可合成让早期生存舒服不少。

**整合包。** 26.1 是一个"必须重做兼容表"的版本：Java 25 卡掉一批只发到 1.21.x 的模组，pack format 84/101.1 卡掉一批材质与数据包，`#dirt` 拆分与 `supports_*` 标签会静默改变世界生成。可用的锚点是 Fabric API 已有对应构建（`0.155.3+26.1.2`，2026-09-07 发布），说明 Fabric 线在 26.1 上是通的；Forge/NeoForge 的具体支持版本本次未能核实到一手数据。

**开发者。** 命令与数据侧要重点迁移：`/time` 返回值语义、`villager.*` 改成 `mob.inventory.*`、告示牌与旗帜默认 `rotation` 从 `0` 改成 `8`。渲染侧要重写 shader 引用与模型 pass 假设。

## 常见坑

1. **用 Java 21 启动 26.1**：启动器直接拒绝。整合包自带的 `java.exe` 若没换，玩家看到的是"游戏崩溃"而不是"Java 版本不符"。
2. **启动参数与默认值打架**：脚本里写死 `-XX:+UseG1GC` 会覆盖新的 ZGC 默认值；`-Xmx` 也会覆盖 4 GB 默认堆。
3. **把 `/time set` 的返回值当时刻用**：26.1 起返回的是时钟累计 tick，旧计时装置会整体偏移。
4. **旧数据包改 `#dirt`**：26.1 把它拆成 `#dirt`/`#mud`/`#moss_blocks`/`#grass_blocks`，写 `#dirt` 不再覆盖泥与苔藓。
5. **材质包的 specular/半透明层**：pass 由 sprite 像素决定，同一张图里混了半透与全透像素时结果可能和旧版不同，必要时用 `force_translucent` 强制。
6. **幼年村民贴图**：改成 base model + overlay 后，旧包里按职业画的幼年贴图会错位。
7. **补丁链**：26.2 的 `prev` 指向 `26.1.2`，说明 26.1 之后还有 `.1`/`.2` 两个补丁版；升级时不要停在 26.1 首发版。
