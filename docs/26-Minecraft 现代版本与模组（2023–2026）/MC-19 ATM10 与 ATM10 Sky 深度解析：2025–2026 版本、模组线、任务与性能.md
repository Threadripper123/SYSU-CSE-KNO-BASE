# MC-19 ATM10 与 ATM10 Sky 深度解析：2025–2026 版本、模组线、任务与性能

## 一句话结论

ATM10 在 2026 年仍是 1.21.1 NeoForge 的“旗舰 kitchen-sink”：8.6 版 495 个模组、4,818 个任务铺在 67 个章节里；ATM10 Sky 不是它的附属模式，而是一条独立维护的空岛线（2.3.1，329 个模组、3,793 个任务/55 章）；真正的新变量是 2026-04 开坑的 ATM11，已跟进到 26.1.2 的 0.14.0-beta，但仍标注 “Super early alpha”。

ATM10 自己的版本节奏也值得单独看。8.x 一个月内连发四版，单版更新以“换模组/修兼容”为主，而不是加内容：

Sky 的版本更碎：2.0.6（2026-09-21，321 模组）→ 2.0.7（10-05，321）→ 2.1.0（10-15，322）→ 2.2.0（10-19，327）→ 2.3.0（10-26，329）→ 2.3.1（10-30，329）。2.3.1 相对 2.3.0 是 0 增删 0 更新，属于纯重打包/修复版。

## 一、ATM10：任务书才是主体

旧库已经写过 ATM10 的模组池、Boss 与挖矿维度，这里只补 2026 年才稳定下来的“任务书工程”视角。

ATM10 的 FTB Quests 数据放在 `config/ftbquests/quests/`，仓库里能直接数出 **67 个 `chapters/*.snbt`**、**860 个语言文件**。第三方任务数据库按同一套 SNBT 统计出 4,818 个任务，两个数字互相印证：章节数可复现，任务总数只有二手统计。

章节规模高度不均，前 10 章就占了任务书的近三分之一：

| 章节 | 任务数 | 主要涉及模组 |
|---|---|---|
| Productive Bees | 251 | Productive Bees |
| Eternal Starlight | 192 | Eternal Starlight |
| Mystical Agriculture | 188 | Mystical Agriculture、KubeJS、Productive Bees |
| Productive Trees | 166 | Productive Trees |
| Just Dire Things | 153 | Just Dire Things |
| Draconic Evolution | 139 | Draconic Evolution |
| Ars Nouveau | 129 | Ars Nouveau |
| Chapter 3: The ATM Star | 127 | AllTheTweaks、Modern Industrialization、AllTheCompressed、EvilCraft |
| Basic Armor | 127 | Twilight Forest、Iron's Spells、Undergarden |
| Immersive Engineering | 126 | Immersive Engineering、AllTheOres |

这种分布解释了“为什么跟着任务书走会突然卡住”：任务书不是一条主线，而是几十条模组线并行；`Chapter 3: The ATM Star` 只有 127 个任务，却是全流程的收束点。

`config/ftbquests/quests/data.snbt` 里有几个直接影响体验的全局键：

```snbt
{
	default_autoclaim_rewards: "disabled"
	detection_delay: 60
	emergency_items_cooldown: 300
	progression_mode: "flexible"
	version: 13
	grid_scale: 0.5d
}
```

- `detection_delay: 60`：任务检测有 60 tick 延迟，刷物品机做“检测即完成”的自动化时要留出这 3 秒。
- `emergency_items_cooldown: 300`：紧急物品领取冷却 300 秒。
- `progression_mode: "flexible"`：允许跨章节跳做，不强制线性。
- `default_autoclaim_rewards: "disabled"`：奖励默认不自动领取，服务器要改就改这里。

`chapter_groups.snbt` 只有 10 个组 ID，说明 67 章在 GUI 里被折叠成 10 个大类；做整合包汉化或重排时，改章节文件不够，还要同步组文件。

语言文件数量也侧面反映了工程量：ATM10 有 **860 个任务语言文件**，Sky 只有 **200 个**。差距不是“Sky 少翻译”，而是 ATM10 的章节文本被拆得更细、每个任务都有独立描述；做汉化或改文案时，ATM10 的维护成本明显更高。官方指南站给 ATM10 编了 435 篇指南、给 Sky 编了 283 篇，比例也与任务规模一致。


## 二、ATM10 Sky：同一套任务引擎，另一套资源逻辑

Sky 的任务数只比 ATM10 少 1,025 个，但资源获取被整体换掉。官方 FAQ 把差异写得很直白：

1. **除下界与末地外，所有模组维度在生存模式不可进入。** 这直接砍掉了 ATM10 里“去 Aether/Starlight 刷材料”的路线，任务奖励与商店成为主要来源。
2. **假玩家不能筛。** 模块化路由器、点击机之类无法与筛子交互；要自动化就用 `Ex Machinis: Divitiae Deorum` 的 **Flux Sieve**。
3. **大量 Mystical Agriculture 种子被移除**，官方目的是把资源生成分散到 Productive Bees 与 GeOres。
4. **下界只生成要塞**，没有堡垒遗迹，也没有 Bastion。
5. 服务器开图必须改 `server.properties` 的 `level-type=skyblockbuilder\:skyblock`，否则会生成普通世界。

GeOres 的“接近满配”摆法在 FAQ 里有具体描述：ME annihilation plane 贴着晶体，只留碎片存储以限制晶体碎裂；生长加速器最多放 1 个红色（boosted）、1 个蓝色（directed），其余面用普通加速器。这套配置比“堆满加速器”更稳，因为红色加速器有上限。

Sky 的服务器迁移还有一个容易丢物品的点：墓碑被左键点掉不会掉物品，要用 `/epitaphs recover <player> <timestamp>` 找回。这个命令在 ATM10 主包里不常用，属于 Sky 特有的运维知识。

## 三、ATM10 与 Sky 的实战取舍

| 维度 | ATM10 | ATM10 Sky |
|---|---|---|
| 开局 | 正常世界，挖矿维度分层明确 | 一棵树/小岛起手，靠筛与蜜蜂 |
| 维度 | 全模组维度可用 | 仅下界/末地，且下界只剩要塞 |
| 资源瓶颈 | 找矿与维度探索 | 筛子、GeOres、蜜蜂、任务奖励 |
| 任务书 | 67 章、4,818 任务 | 55 章、3,793 任务 |
| 服务器关键配置 | `view-distance=8`、`simulation-distance=5` | 额外要 `level-type=skyblockbuilder\:skyblock` |
| 适合 | 想完整玩 2026 年最大模组池 | 玩过 ATM10、想换资源节奏 |

如果只开一个服，ATM10 的容错更高：Sky 的“维度禁用 + 假玩家禁用”会让很多从 ATM10 抄来的自动化直接失效。反过来，Sky 的进度压力更小，因为任务奖励会补资源。

## 四、ATM11：现在只适合“看”，不适合“住”

ATM11 的 CurseForge 页自述是 “Super early alpha for 26.1.2”，2026-04-15 建项，到 11-03 才 0.14.0-beta。它跟随的是 2026 年的新年号版本线：26.1 Tiny Takeover（2026-03-24，最低 Java SE 25）、26.2 Chaos Cubed（2026-06-16）、26.3 Wilderness Bound（2026-09-15）。也就是说 ATM11 跳过了 1.21.2–1.21.11 的整段积累，直接在 26.x 上重建。

对玩家的实际含义：
- 126 万下载说明“尝鲜需求”很大，但 alpha 版本不适合长期存档；
- 26.1 起最低 Java 25，和老 1.21.1 服的 Java 21 运行环境不能共用；
- 模组生态在 26.x 上还没补齐，ATM11 的模组数远低于 ATM10 的 495，任务书也未成型。

## 五、性能与配置：官方服务端脚本给了硬数字

ATM10 每个版本都在 CurseForge 旁边挂官方 ServerFiles。以 8.2 的服务端包为例，几个可以直接照抄的事实：

- 首次启动脚本会安装 **NeoForge 21.1.251**，并在 Java < 21 时拒绝启动；
- 只有在 `server.properties` 不存在时才写入 `allow-flight=true`、`max-tick-time=180000`、`view-distance=8`、`simulation-distance=5`；
- 自带 `user_jvm_args.txt` 写的是 `-Xms4G -Xmx8G`。

最后一条是“能启动”而不是“能长期跑”。第三方托管商的实测口径是 1–3 人约 **9.5–10.5 GB**，推荐 12 GB 档；客户端则普遍给 8–10 GB。换句话说，官方脚本的 8 GB 上限只适合单人/验证启动，多人要往上加。

另外两个容易忽略的点：
- 官方服务端包**不含备份模组**，而客户端包带 Simple Backups，服主需要自己补备份；
- Compact Machines 会在无人在线时继续吃内存，ATM 贡献者的建议是把机器保持在两侧都 chunk-load。


## 六、Sky 的资源路线怎么选

Sky 把“挖矿”换成了三条互相补位的路线，选错路线会让前期卡很久：

| 路线 | 关键方块/物品 | 优点 | 限制 |
|---|---|---|---|
| 筛子 | §Ex Machinis§ 筛子、Flux Sieve | 前期最快出砂砾/尘土/矿石碎片 | 假玩家不能交互，自动化必须用 Flux Sieve |
| GeOres | GeOre 晶体 + 生长加速器 | 单晶体可持续产矿，后期最稳 | 红色加速器最多 1 个、蓝色 1 个 |
| Productive Bees | 蜜蜂 + 蜂箱升级 | 可产出部分金属与资源 | 需要基因/蜂种投资，启动慢 |

官方的 GeOre 满配示例值得抄：ME annihilation plane 直接贴晶体，存储只收碎片，晶体一碎就停，避免“无限产出把存储打爆”；加速器按“1 红 + 1 蓝 + 其余普通”布置，而不是全堆红色。这个细节在老库的 ATM10 攻略里没有，因为主包不靠 GeOre 起手。

## 七、版本选择与升级检查清单

| 你的情况 | 建议版本 | 理由 |
|---|---|---|
| 第一次玩 ATM 系 | ATM10 8.6 | 模组最全、指南 435 篇、任务 4,818 |
| 玩过 ATM10 想换节奏 | Sky 2.3.1 | 资源逻辑独立，任务 3,793 |
| 想尝 26.x 新版本 | ATM11 0.14.0-beta | 仅试玩，别长期存档 |
| 想玩 Create 航空 | ATM10 Aeronautics 0.8.0 | 独立分支，跟进较慢 |

升级前按这个顺序检查，能避开大部分“升完进不去”：
1. 看目标版本是“0 增删”还是“换模组”：8.6 是 42 个模组更新、0 增删，风险低；8.4→8.5 有 -1，需看被移除的是否是你依赖的。
2. 备份 §saves/<world>§ 与 §serverconfig§，任务进度在 §config/ftbquests§ 与存档两侧都有状态。
3. Sky 服确认 §level-type§ 没被托管面板重置。
4. 客户端与服务端模组列表必须逐项一致，ATM 系对版本错配很敏感。
5. 升完先跑一次 §/ftbquests editing_mode§ 检查任务书能否打开，再放玩家进服。

## 对玩家 / 整合包作者 / 服主的实际影响

- **玩家**：2026 年选 ATM10 仍是“内容最多、攻略最全”的选择；Sky 适合第二周目。看到 8.6 这种“42 个模组更新、0 增删”的版本，不必急着升，等 3–5 天看 issue 更划算。
- **整合包作者**：ATM10 的任务书是现成的 SNBT 教材——67 章、860 语言文件、10 个组，结构完整；要学“大包怎么组织任务”直接读它的 `chapters/` 比看文档快。
- **服主**：Sky 服必须改 `level-type`，否则第一晚就会生成普通世界；ATM10 服要把 `view-distance` 压到 8、`simulation-distance` 压到 5，并把 `-Xmx` 提到 10–12G。

## 常见坑

1. **把 Sky 当 ATM10 的“空岛预设”**：它是独立项目（1298402），任务、模组数、资源逻辑都不同，整合包不能互换。
2. **在 Sky 里找 Aether/Starlight**：官方 FAQ 明确说模组维度生存不可进，别再按 ATM10 的攻略跑。
3. **用假玩家自动筛**：筛子不认假玩家，必须换 Flux Sieve。
4. **服务端只给 8G**：官方 `user_jvm_args.txt` 的 `-Xmx8G` 是保守值，1–3 人实际要 9.5–10.5G。
5. **任务完成不了就改 SNBT**：先在任务界面右下开编辑模式，右键 Complete Instantly；直接改文件容易把 `version: 13` 的数据写坏。
6. **ATM11 当正式包开服**：0.14.0-beta 且 26.x 模组生态未齐，长期存档风险高。


## 八、2026 年的三个判断

1. **1.21.1 仍是主战场。** ATM10、ATM10 Sky、BMC5 全部压在这条线上，ATM11 虽已开坑但只是 alpha；对普通玩家，2026 年买新电脑后最稳的选择仍是 1.21.1 的成熟包。
2. **任务书规模成了竞争力，也成了维护负担。** 4,818 个任务意味着每次模组大版本都要重跑检测；8.6 这种“42 更新、0 增删”的版本，本质是在不破坏任务书的前提下换底层。
3. **Sky 分支的价值是资源链重构，不是换地图。** 禁维度、禁假玩家、移种子三件事一起做，才让它和主包产生真正的玩法差异；只把它当“空岛皮肤”会低估改造成本。
