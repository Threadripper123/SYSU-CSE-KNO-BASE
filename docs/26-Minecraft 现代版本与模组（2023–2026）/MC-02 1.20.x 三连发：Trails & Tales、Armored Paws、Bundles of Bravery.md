# MC-02 1.20.x 三连发：Trails & Tales、Armored Paws、Bundles of Bravery

> 主题库：Minecraft 现代版本与模组（2023–2026）　｜　源文件：（纯文本条目）　｜　7,092 字符　｜　41 个片段　｜　更新于 2026-11-15
> 资料截至 2026-11-15；覆盖 2023-11 至 2026-11，重点 2024–2026。

**一句话结论**：这三个 drop 的真正区别不在「加了多少内容」，而在「技术姿态」——1.20 把叙事与考古做进系统，1.20.5 用数据组件重写了物品的存储方式（生态断裂点），1.21.2 的收纳袋则证明 drop 可以小到只改一个物品和一套 UI。但必须先纠正一个编号事实：Bundles of Bravery 的版本号是 1.21.2/1.21.3，并不在 1.20.x 序列里；把它和 1.20 周期的两个 drop 并置，是「发行节奏」意义下的归类，不是版本号归类。

## 一、先把编号说清楚

「1.20.x 三连发」这个说法在中文社区很常见，但它混了两个维度。按版本号看：

| 名称 | 版本 | 发布日 | 是否属 1.20.x |
|---|---|---|---|
| Trails & Tales | 1.20 | 2023-06-07 | 是（起始大版本） |
| Bats and Pots | 1.20.3 / 1.20.4 | 2023-12-05 / 2023-12-07 | 是 |
| Armored Paws | 1.20.5 / 1.20.6 | 2024-04-23 / 2024-04-29 | 是（1.20 序列终点） |
| Bundles of Bravery | 1.21.2 / 1.21.3 | 2024-10-22 / 2024-10-23 | 否，属 1.21.x |

1.20 序列在 1.20.6 就结束了，之后是 1.21 Tricky Trials。收纳袋之所以被误记进「1.20 三连发」，是因为它常被拿来和 Armored Paws 对比：两者都是「小而专」的 drop，都只有一两个主打物品。但版本号上它明确属于 1.21.2。本文按标题覆盖这三者，编号上会逐一标注。

## 三、Trails & Tales（1.20）：把「叙事」做进系统

这次更新的官方定位是「让玩家通过新方块与故事表达自己」。落地的东西可以归成四类：

**建筑素材**。樱花木全套（含樱花树苗、粉红花瓣）、竹木全套（竹板、竹 mosaic、竹筏与带箱竹筏）、各木材的吊牌（hanging sign）、雕纹书架（chiseled bookshelf，可插书）、猪灵头。这一批直接改写了建筑党的调色板——粉红花瓣落地会生成粉色粒子，是第一批「装饰性粒子方块」。

**考古系统**。刷子（brush）在可疑的沙与可疑的沙砾上刷出陶片、纹饰陶罐、音乐唱片与嗅探兽蛋。考古点分布在沙漠神殿、海底废墟、trail ruins 等结构；trail ruins 是本版本新增的考古专属结构。

**生物**。骆驼（可载两人、有冲刺）、嗅探兽（从蛋孵化，能嗅出远古种子 torchflower 与 pitcher plant），以及作为考古副产物的各类陶片。

**进阶系统**。锻造模板（smithing template）把下界合金升级变成「模板 + 材料」的配方，并新增 12 种盔甲纹饰；校准幽匿感测体（calibrated sculk sensor）用于精确过滤振动频率。

| 类别 | 模板 |
|---|---|
| 升级 | Netherite Upgrade（下界合金升级） |
| 纹饰 | Coast、Dune、Eye、Rib、Sentry、Silence、Snout |
| 纹饰 | Spire、Tide、Vex、Ward、Wild |

纹饰是纯外观，不提供数值加成，但它把「盔甲换色」从整件改变成了局部花纹，这也是 1.20 被叫作「表达自我」版本的原因之一。

技术上，1.20 把告示牌的 NBT 从 `Text1`–`Text4` 改成 `front_text.messages[]` / `back_text.messages[]`，把 `alternative` 谓词改名为 `any_of`，并收拢了三个 advancement 触发器的字段。数据包格式 15 就是这些改动的产物。

### 1.20.2：被低估的那一次

1.20.2 常被当成「大版本后的补丁」，但它引入的函数宏（function macro）是数据包写法的一次换代。此前函数参数只能靠记分板传递；有了宏之后，函数里可以写以美元符号开头的行，用 `$(参数名)` 占位，由 `/function <id> {参数:值}` 传入：

```
$give $(target) minecraft:$(item) 1
```

调用侧写成 `/function demo:give {target:"@s",item:"stone"}`。这让「一个函数服务多种用途」成为可能，也让数据包作者第一次有了「带参数的子程序」。代价是宏行不能嵌套调用、每次执行有额外开销，滥用会明显拖慢服务端。

同一版本还把效果（effect）的 NBT 从数字 ID 改成命名空间 ID（`1` → `minecraft:speed`），并加入村民交易平衡的实验开关。数据包格式因此从 15 跳到 18。

## 四、Bats and Pots（1.20.3）：一个被追认的 drop

1.20.3 发布时并没有代号，官方也没叫它 drop。它当时被理解为「1.20 的第三次次要更新」：改进盾牌手感、给饰纹陶罐加功能、重做蝙蝠外观、让聊天组件序列化更严格，以及一个对技术服主极其重要的命令——`/tick`。

`/tick` 提供 `query`、`rate`、`freeze`、`step`、`unfreeze`、`sprint` 六个子命令，可以冻结游戏、按 tick 步进、把目标 tick 速率设到 1.0–10000.0 之间。它需要权限等级 3，默认在命令方块和数据包里不可用——这点常被忽略，很多人写进数据包后发现根本不执行。

1.20.3 还开了 1.21 的实验开关：合成器、试炼刷怪笼、旋风人第一次以实验内容出现。也就是说 Tricky Trials 的一半机制，在 2023 年 12 月就能摸到了。

直到 2024 年 9 月，官方才在社交平台上把 1.20.3 追认为 drop 并命名为 Bats and Pots。所以 2023 年的旧文章里搜不到这个名字，不是资料错了，是当时确实没有。

## 五、Armored Paws（1.20.5）：内容小、技术大

表面看它只加了犰狳和狼铠：犰狳在热带草原与恶地生成，掉落犰狳鳞甲（也可用刷子刷），鳞甲用于合成与修复狼铠；狼按生物群系分成多个变种。内容量在四个 drop 里算最小的一档。

但它同时是 2023–2026 这段里最大的一次技术断裂：物品堆叠不再用无结构 NBT 描述，改用结构化数据组件（data component）。旧写法与 1.20.5+ 的对应关系大致是：

| 旧 NBT 路径（≤1.20.4） | 新组件 ID（1.20.5+） |
|---|---|
| `display.Name` | `minecraft:custom_name` |
| `display.Lore` | `minecraft:lore` |
| `Enchantments` | `minecraft:enchantments` |
| `Damage` | `minecraft:damage` |
| `AttributeModifiers` | `minecraft:attribute_modifiers` |
| `Unbreakable` | `minecraft:unbreakable` |
| `CanDestroy` / `CanPlaceOn` | `minecraft:can_break` / `minecraft:can_place_on` |
| `tag`（自定义数据） | `minecraft:custom_data` |

后果是连锁的：所有用 `/give ... {display:{Name:...}}` 的命令、所有在战利品表里写 NBT 的数据包、所有读写物品 NBT 的模组，在 1.20.5 之后全部要改。这也解释了为什么 1.20.1 至今仍是模组聚集地——不是它内容好，是跨过 1.20.5 的成本太高。


另一个容易被忽略的点：1.20.5 同时更新了「Update 1.21」实验，把沼骸（bogged）、宝库（vault）、旋风棒、风弹、重锤与不祥事件塞进了实验开关。也就是说，Tricky Trials 的核心战斗循环在 2024 年 4 月就已经可以试玩了，只是被实验开关挡着。理解这一点，才能解释为什么 1.21 正式发布时「内容量看起来不大」——大半机制早已随 1.20.5 落地。

实验开关本身也是双刃剑：它让官方能提前放内容收集反馈，但实验内容随时可能改名、改数值甚至删除。整合包如果把实验内容当正式内容写进配方与任务线，升级后开关移除时就会丢东西。稳妥做法是：实验内容只做「体验区」，不进入主线进度。

同版本还有两个硬门槛：Java 21（此前是 Java 17）和 64 位系统。1.20.5 是第一个要求这两项的正式版。

顺带一提，1.20.5 本身带一个已知的数据丢失问题：商人羊驼的物品栏在升级时会错位，可能导致物品丢失。1.20.6 就是为修这个而发的。跨版本升级时不要停在 1.20.5。

## 六、Bundles of Bravery（1.21.2）：最小的 drop

它只做三件事：加收纳袋、加两个旗帜图案、重排稀有度。收纳袋的规则值得记牢：

- 可容纳最多 64 个「堆叠单位」，折算方式是 `64 / 该物品的堆叠上限`：上限 64 的物品占 1 格，上限 16 的占 4 格，不可堆叠的占满 64 格（其他收纳袋除外）。换句话说，装满不可堆叠物品的收纳袋只装得下 1 件。
- 由线 + 皮革合成，可染成 16 色；染色后不能恢复默认色（官方标记为无效而非 bug）。
- 潜影盒不能放进收纳袋；收纳袋可以放进收纳袋，占用 4 格加上内层已用格数。

两个旗帜图案 Field Masoned 与 Bordure Indented 是为与基岩版对齐而补的。稀有度重排则把物品的稀有度颜色与实际获取难度重新对齐：普通（common，白色）、少见（uncommon，黄色）、稀有（rare，青色）、史诗（epic，紫色）四档的分界被重新划线，很多原本「紫色」的物品降了档。它影响 tooltip 颜色与部分掉落逻辑的引用，不影响实际掉率。

1.21.2 同时把冬更（The Garden Awakens）的苍白花园与嘎枝放进了实验开关——这是 drop 体系里的常规做法：下一个 drop 的内容，先在当前版本的实验里露面。1.21.3 是它的热修，主要修 Realms 连接。

## 七、对玩家、整合包作者与服主的实际影响

**玩家**：这三个 drop 的内容门槛都不高，1.20 的考古与樱花林几乎不改变生存难度，犰狳与狼铠属于「锦上添花」，收纳袋是纯 QoL。真正会绊人的是版本升级：1.20.1 → 1.20.5 会同时撞上 Java 17→21、资源包 15→32、数据包 15→41 三道墙。

**整合包作者**：如果你的包停在 1.20.1，那 1.20.5 的数据组件是唯一需要评估的迁移成本；如果你在 1.21.2 之后建包，则要同时处理 1.21.2 的属性 ID 去前缀（数据包 57）与 1.21.5 的文本组件改动。实践中最省事的做法是「一个包只服务一个 drop」，跨 drop 直接开新实例，而不是原地升级。

**服主**：1.20.3 的 `/tick` 是排障利器，但它需要权限等级 3；给管理员 `/op` 即可，不要指望在命令方块里跑。另外 1.20.5 的羊驼 bug 意味着「升级到 1.20.5 就停」是最坏的选择，要么留 1.20.4，要么直接 1.20.6。

## 八、常见坑

1. **把收纳袋记成 1.20.x**：它是 1.21.2 的内容，1.20.6 里没有。
2. **在 1.20.5 上停留**：商人羊驼物品栏错位会导致物品丢失，务必升到 1.20.6。
3. **继续用旧 NBT 写物品**：1.20.5 起 `{display:{Name:...}}` 不再生效，要改用组件语法。
4. **以为 `/tick` 在数据包里可用**：它默认只对权限等级 3 开放，命令方块与函数里都不执行。
5. **资源包跨档复用**：15 → 22 → 32 → 42，跨档基本等于重做，别指望「只报 incompatibility 但还能用」。
6. **把 1.20.2 当纯热修**：它引入了函数宏与村民交易平衡实验，数据包写法有实质变化。
8. **把实验内容当正式内容**：1.20.3/1.20.5/1.21.2 都带实验开关，实验内容随时会改；写进主线任务后，开关一撤就断档。
7. **忘记 1.20 的告示牌 NBT 改动**：`Text1` 系列已废弃，旧数据包里的告示牌内容会读不出来。

- 1.20.5 数据组件的「旧路径 → 新组件」对照表按官方组件命名整理常用项，未逐条比对全部组件；生僻组件（如工具提示显示控制）未列入。
- 狼变种的具体数量与命名未逐一核实，文中只写「按生物群系分多个变种」。

- 收纳袋染色是否能洗回默认色，文中采用官方 bug 追踪结论「不可恢复」，未做游戏内实测。
