# MC-14 科技模组 2025–2026：Create 6、AE2、Mekanism、GregTech Modern、Powah

> 资料截至 2026-11-15；覆盖 2023-11 至 2026-11，重点 2024–2026。

**一句话结论**：2025–2026 年的科技模组进入"1.21.1 长期驻留、26.x 分批移植"的双轨期——Create 6 把工厂物流改造成"纸板包裹 + 库存网络"，但到 2026-11 仍只支持到 1.21.1；AE2 率先用与 MC 对齐的 26.x 版本号完成移植；Mekanism 与 GregTech Modern 的主力仍在 1.21.1（GTM 的 26.1 分支在开发中）；Powah 的 26.x 版本还停在 alpha。选包时第一筛选条件应是"目标 MC 版本有没有稳定版"，而不是模组版本号的大小。

## 一、Create 6：把"物流"做成一等公民

Create 6.0.0 于 2025-03-01 首发于 1.21.1，1.20.1 玩家要等到 2025-06-07 的 6.0.5。这次更新的核心不是新增几个齿轮，而是把"工厂内部运输"抽象成包裹系统：Packager 与 Re-packager 负责把物品打成纸板包裹，Cardboard packages 是统一载体，Package Frogport 与 Package Postbox 负责收发，Stock Link 把容器接入库存网络，Stock Ticker（6.0.10 的更新日志里写作 Stock Keeper）汇总库存，Redstone Requester 与 Factory Gauge 让红石信号可以"下单"，Package Filter 决定包裹里装什么。

配套改动同样关键：列车时刻表新增"投递/取回包裹"指令，意味着铁路第一次能参与厂内物流；Basins 取消了"每格最多 16 个物品"的限制，批量合成的吞吐不再被卡；机械合成器减少了空动画帧的浪费；在常见的圆石生成场景里，静止的钻头会跳过"先破坏方块"直接产出到下方容器。绳索默认最大长度提高到 384。渲染层换代到 Flywheel 1.0，这是 6.0 对整合包最硬的门槛——旧的 Flywheel 0.6.x 不能混用。

6.0.10（2026-04-21）是这条线目前最后一个版本，包含两个对自动化很实际的内容：Stock Keeper 与配方查看器（REI/JEI/EMI）的同步支持四种模式（Disabled、只从查看器同步、只向查看器同步、双向）；修复了同一存储（例如双箱）上的多个 Stock Link 重复上报数量的问题，以及 Postbox 在被人打开时被破坏导致的复制漏洞。同版本还把列车的 `maxAssemblyLength` 限制为 512、`maxBogeyCount` 限制为 200，避免超长列车把服务端拖垮。

但 Create 的 MC 支持面仍是 1.18.2、1.19.2、1.20.1、1.21.1 四档。2025-09 之后的 1.21.9/1.21.11 与 26.x 全都没有官方版本，这在事实上把大量科技整合包钉在了 1.21.1。

## 二、AE2：版本号与 MC 对齐的先行者

AE2 在 1.21.1 上走完了 19.x 全程：19.0.20-beta（2024-08-09）→19.0.27（2024-12-13）→19.1.x（2025-01）→19.2.0-beta（2025-01-29）→19.2.19（2026-11-09）。19.0.20-beta 的 PR 列表里已经出现 Network Ticking Optimizations、P2P 频率在内存卡使用时被重置的修复、以及"仅当值真的改变时才保存客户端配置"这类降低文件锁风险的改动。1.20.1 线由 15.4.12（2026-10-28）继续维护。

26.x 线则换了命名策略：26.1.6-alpha（2026-05-05）的标题直接是"Finished 26.1 port"，随后是 26.1.13-beta（2026-09-30）、26.2.1-alpha（2026-10-01）、26.3.1-alpha（2026-10-03）。版本号与 MC 版本对齐，好处是"看到 26.3.x 就知道能装 26.3"，代价是老玩家熟悉的 19.x/15.x 序列彻底断档，升级时需要重新建立"哪个数字对应哪个 MC"的心智模型。

机制层面 AE2 这几年没有推翻重来，仍是"频道 + 控制器 + 子网"的三件套：普通线缆承载 8 条频道、致密线缆 32 条，没有控制器的 ad-hoc 网络最多 8 条频道；样板供应器（Pattern Provider）把样板推给相邻的分子装配室或机器，接口（Interface）把网络库存暴露给外部设备，存储总线（Storage Bus）把箱子、抽屉接入网络，P2P 隧道用来搬运物品、流体、能量、红石甚至频道，子网则用来把"自动化的一小段"从主网隔离出去，避免频道被吃光。19.2 线的优化主要落在网络 tick 与同步上，对大型基地是实打实的减负。

自动合成则依赖"合成 CPU 多方块"：合成单元（Crafting Storage）提供任务容量，协同处理单元（Co-Processing Unit）提供并行度，合成监控器显示进度；样板供应器把样板交给相邻的分子装配室执行，产物回收到网络。实战里最常见的瓶颈不是 CPU 太小，而是样板供应器只朝一个方向推样板、或者频道不够导致供应器掉线——所以大型基地通常把"每个产物一组供应器 + 分子装配室"做成独立子网，再用接口把结果并回主网。

## 三、Mekanism：10.7 停在 1.21.1，26.x 还在分支里

Mekanism 的 1.21.1 线目前是 v1.21.1-10.7.19.85（2026-04-10），往前是 10.7.18.84（2026-02-14）与 10.7.17.83（2025-10-21）。GitHub 仓库里已经建好 `1.21.11`、`26.1`、`26.2`、`26.3` 四条分支，默认分支甚至已经切到 `26.3`，但截至 2026-11-15 没有任何 26.x 的正式发布，Modrinth 上的支持列表也只到 1.21.1。换言之：代码在往前赶，成品还没到。

它吸引整合包的地方仍是那套"一条矿线吃到五倍"的体系：富集仓做 2 倍，净化仓、注入仓、溶解仓把倍率推到 3–5 倍；再往上是用电力和气体撑起来的聚变反应堆、反物质 SPS、数字采矿机、QIO 存储与传送器。这套体系的问题也在这里——它需要大量电力与气体基础设施，前期投入远高于 AE2 或 Refined Storage，适合中后期包而不是轻量科技包。

存储侧的 QIO 是 Mekanism 自己的"数码存储"：QIO Drive Array 装 QIO Drive，QIO Dashboard 做终端，支持频率绑定与无线访问；它和 AE2/RS 的定位重叠，但更偏"单基地、少频道、低学习成本"。电力侧从热力发电机、太阳能、风力起步，中后期靠燃气、裂变与聚变堆，能量单位是 J（焦耳），与 FE 的换算在配置里可调——这也是整合包作者最常改的一处平衡点。

## 四、GregTech Modern：7.5.x 在 1.20.1，1.21 是 8.0.0 快照

GTM 的稳定线是 1.20.1 的 v7.5.3-1.20.1（2026-04-12）。v7.5.0（2026-02-08）的更新日志信息量很大：喷漆输出总线可以匹配喷漆输入总线、输出总线加了过滤槽、机器复制/粘贴卡现在能复制管道与 cover 及其设置、矿石提纯加入 gem slurry 配方、配方失败会显示原因、喷漆罐可以给 AE2 的 Colorable BlockEntity 上色、加入 HV/IV 螺丝刀与链锯、配方条件支持生物群系 tag、Jade 能显示电池信息、温度可选摄氏显示、Central Monitor 支持用占位符渲染其它模块——同一版本还修掉了 Central Monitor 允许本地文件包含的安全漏洞。

1.21.1 线有 v7.0.0/v7.0.2 两个稳定 tag，另有滚动 tag `latest-1.21`，其发布名是"1.21-8.0.0 SNAPSHOT"（2026-11-13 仍在更新）。仓库分支只有 `1.19.2`、`1.20.1`、`1.21`、`26.1`，26.2/26.3 尚未开分支。电压层级仍是 GT 的老规矩：ULV 8、LV 32、MV 128、HV 512、EV 2048、IV 8192、LuV 32768、ZPM 131072、UV 524288、UHV 2097152（EU/t），机器、线缆与仓室的配方都围绕这套阶梯设计。

GTM 的玩法骨架是多方块：一个控制器决定这台机器"是什么"，能源仓决定能吃到哪一档电压，输入/输出仓决定能接多少种物品与流体，维护仓则承担维护事件。7.5.0 新增的"配方失败原因显示"对新手尤其重要——过去机器不工作时只能猜是电压不够、仓室不匹配还是配方条件不满足，现在界面会直接给出原因。

对玩家的现实含义：想在 1.21.1 上玩 GTM，得接受 8.0.0 SNAPSHOT 的不稳定；想要稳定，就留在 1.20.1 的 7.5.x。26.x 目前没有可玩的 GTM。

## 五、Powah：跨 MC 线"跳大版本"

Powah 的版本号在 26.x 时代最容易被误读：1.21.1 线是 6.2.10-neoforge（2026-04-29），26.1.2 线是 7.0.4-alpha（2026-05-02），26.3 线直接跳到 9.0.0-alpha-neoforge（2026-11-11），中间还有 8.0.1-alpha。三条线各自独立，6、7、9 之间没有"谁更新"的关系。

内容上 Powah 仍是"从 Starter 到 Nitro 七级"的发电与储能套装：Furnator（烧燃料）、Magmator（岩浆）、Thermo Generator（热）、Solar Panel（太阳能）、Reactor（铀反应堆），配套 Energizing Rod 做充能、能量单元与线缆做传输。它的定位是"便宜、好用、不需要复杂管线"，和 Mekanism/GTM 的重工业路线互补，常见于中前期供电。

## 对玩家、整合包与开发者的实际影响

**整合包作者**：1.21.1 仍是 2025–2026 科技包的主战场，因为 Create 6、Mekanism 10.7、GTM 8.0.0 快照、Powah 6.2、AE2 19.2 能在同一版本上凑齐。26.x 目前只有 AE2（且部分是 beta/alpha）、Powah alpha、以及存储类的 Sophisticated/Functional Storage，做不出"Create + 重工业"的完整科技包。

**升级路径**：从 1.21.1 迁到 26.x 时，AE2 要从 19.x 跳到 26.x，配方与数据组件都会变；Create 没有对应版本，任何依赖 Create 的产线都得重做或留在旧版。26.1 起 Java 要求提升到 Java SE 25（26.1 于 2026-03-24 发布），服务端与客户端都要先升级运行时。

**服务器性能**：AE2 19.0.20-beta 起持续做网络 tick 优化；Create 6.0.10 明确写了"进一步优化装置碰撞"与 `GlobalRailwayManager#playerLogin` 的优化，并把列车装配长度与转向架数量设了上限。这两项对大型服务器比新增方块更有价值。

**开发者**：Create 6 的渲染依赖 Flywheel 1.0，扩展模组要跟着改渲染接入；AE2 的 26.x 版本号策略意味着构建脚本里的版本判断不能再假设"数字越大越新"；GTM 的 8.0.0 快照期不建议作为依赖基线。

## 常见坑与局限

1. **跨 MC 线比版本号**：Powah 9.0.0 不是"比 6.2.10 更成熟"，它只是 26.3 线的第一个 alpha；AE2 的 26.3.1-alpha 同理。
2. **双线并存下错文件**：Create、AE2、Mekanism 都同时维护 1.20.1 与 1.21.1，下载页默认给的往往不是你要的那条线。
3. **alpha/snapshot 混进长期存档**：GTM 的 `latest-1.21` 与 Powah 的 `9.0.0-alpha` 都明确标注为快照/alpha，适合测试，不适合长期服务器。
4. **Flywheel 版本错配**：Create 6.0 需要 Flywheel 1.0；把 0.6.x 的 Flywheel 留在 `mods` 里会直接崩或渲染异常。
5. **Create 6 存档迁移**：红石链接降为安山岩级、材料改用 transmitter，旧产线里的链接可能需要重做；Basins 取消每格 16 个的限制后，原有产线的缓冲与溢出行为会变。

- Powah 的 1.20.1 版本号未核对；26.x 三条线的 alpha 稳定性未做实测。
