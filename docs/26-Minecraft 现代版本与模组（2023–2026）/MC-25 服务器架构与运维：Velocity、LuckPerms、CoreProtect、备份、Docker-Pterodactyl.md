# MC-25 服务器架构与运维：Velocity、LuckPerms、CoreProtect、备份、Docker/Pterodactyl

## 一句话结论

把服务器从"一个 jar 加一个世界"做成"代理 + 多子服 + 共享权限库 + 审计 + 可恢复备份"，真正的门槛不在装插件，而在**数据一致性**：权限要有一个唯一真相源，审计要能回答"三天前谁拆了这面墙"，备份要能真的恢复回来。2026 年这套栈的新变量是：Velocity 进入 4.x 与 3.x 并存期、Pterodactyl 的 2.0 进入 beta 而 1.15 仍在出安全补丁、Paper 的下载接口换代导致老脚本静默失效。

一个容易被忽略的事实：**Velocity 的版本线还没收敛**。下载接口里同时能看到 `4.0.0` 家族的 `4.3.2-SNAPSHOT`、`4.3.1`、`4.3.0`、`4.2.1-SNAPSHOT`，以及 `3.0.0` 家族的 `3.5.1`、`3.5.0`。这意味着选型时必须先决定跟哪条线，插件的兼容声明也是按线写的。

顺带说一句拓扑判断：代理不是"人多了就该上"，而是"需要在多个世界或模式之间无感切换时才上"。如果只有一张生存图、没有大厅也没有小游戏，加一层代理只会多一跳延迟和一个新的故障点——不少服主的"优化"最后变成了多一个需要盯着的东西。

## 代理层：Velocity 与它的三种转发

Velocity 的定位是"现代的新一代代理"（仓库自述），核心价值是把玩家连接与后端子服解耦：玩家连代理，代理按规则把他送到大厅、生存、小游戏。

转发模式只有三种，且**只能选一种，不能混用**：

| 模式 | 安全性 | 版本要求 | 适用 |
| --- | --- | --- | --- |
| Velocity modern forwarding | 最高，二进制格式 + MAC 校验 | MC 1.13+ | 现代服首选 |
| BungeeCord（legacy） | 低，可被伪造 | 兼容面最广 | 必须支持 1.13 以下时 |
| BungeeGuard | 中，legacy + 共享密钥 | 同 legacy | 被迫用 legacy 时的补强 |

官方文档明确写了 modern forwarding 的边界：它用 MAC 让子服难以被伪装成代理，因此安全性远高于 legacy；但它**不兼容 1.13 以下的客户端，也不兼容 ProtocolSupport 插件**。如果你的服还在收 1.8 客户端，那就只能走 legacy，这等于接受"子服可被直连伪造"的风险——补救办法是让子服只监听内网或加防火墙白名单，而不是指望插件。

**2026-10-27 的 `4.3.1`** 值得单独提：它的更新说明是"改进 legacy 插件消息与非法数据包的缓冲处理"，并被标注为**建议所有用户升级的安全更新**。代理层是唯一暴露在公网的组件，这类补丁不要拖。

## 权限：LuckPerms 的唯一真相源

LuckPerms 是权限插件，这句话没错，但运维上更重要的是它的**存储后端决定架构**：

- 单服：文件存储够用，备份跟着世界目录一起打包即可。
- 多子服（哪怕只有两个）：必须让所有子服连**同一个数据库**。否则玩家在大厅是 VIP、进生存变默认组，这类工单会反复出现。
- 代理侧也要装一份，并指向同一个库，否则登录时的权限判断与后端不一致。

当前版本 `v5.5.87`（2026-10-06），Velocity 构建是 `v5.5.71-velocity`（2026-08-06）——**两侧版本号不同步是正常的**，不要为了"对齐版本号"去降级。

实践上的三条纪律：权限只通过组下发，不给玩家单独节点；所有改动留命令记录（谁在什么时候给了什么）；数据库本身纳入备份，且备份频率要高于世界——权限表很小，但丢了就是全服权限重置。
## 审计：CoreProtect 与"能不能回滚"

CoreProtect 是数据记录与反破坏工具（仓库自述），当前 `v24.1`（2026-09-24），采用 Artistic License 2.0。它回答三个问题：谁放的、谁拆的、什么时候。

它的运维成本经常被低估——**日志表长得比你预期快**。一个 30 人活跃服，方块交互日志几个月就能到几十 GB 量级（实际取决于交互频率与保留策略）。所以部署时就要定三件事：

1. 日志库放哪：和权限库同实例可以，但要监控磁盘；
2. 保留多久：按定期清理的策略裁剪，别等磁盘满；
3. 回滚的边界：它回滚方块与容器状态，**回滚不了玩家背包、经验与实体**。

第二条最容易被忽略：很多人第一次用回滚，是在服务器已经写满磁盘、数据库拒绝写入之后——那时连"回滚所需的日志"本身都不完整了。

## 备份：一致性比频率更重要

备份最常见的误区是"我每天打包一次，所以安全"。真正决定能不能恢复的是**打包时文件是否处于一致状态**。

一个可靠的最小流程：

1. 关闭自动保存：`save-off`；
2. 强制落盘：`save-all flush`；
3. 打包世界目录与配置（此时写入已停）；
4. 恢复：`save-on`。

跳过第 1、2 步直接打包一个正在写入的世界，得到的是一个"能解压、能启动、但区块半新半旧"的存档——这种损坏往往几周后才暴露，而且无法回滚。

策略按 3-2-1 走：至少三份、两种介质、一份异地。

| 层级 | 频率 | 保留 | 目的 |
| --- | --- | --- | --- |
| 快照 | 每 1–6 小时 | 24–48 份 | 误操作、区块损坏 |
| 日备 | 每天 | 7–14 天 | 撤销一周内的破坏 |
| 周全量 | 每周 | 4–8 周 | 大版本升级前的回退点 |

**没有验证过的备份等于没有备份。** 定期把最新备份解到另一台机器、用不同端口起一个实例、走进去看一眼——十分钟的事，能避免"出事时才发现备份一直是空文件"。

## 容器化：Docker 与 Pterodactyl 的分工

Pterodactyl 是两层架构：**Panel 是 Web 控制面**（PHP + React，自述里还含 Go 组件），**Wings 是每个节点上的控制面守护进程**（Go），由它在本机把每个游戏服跑在独立的 Docker 容器里。所以"面板挂了"和"服务器挂了"是两件事：Panel 宕机，玩家照样在线；Wings 或 Docker 出问题，容器才会掉。

版本状态要看清：

- `v1.15.2`（2026-10-21）是稳定线最新补丁，说明里提到针对 `CVE-2026-109618` 与 `CVE-2026-109619` 的安全修复，镜像升到 PHP `8.3.36`；不用 Docker 的部署要把 PHP 升到 `8.2.35` 或 `8.3.36`，并且**所有 PHP 包一起升**。
- `v2.0.0-beta.2`（2026-10-14）是下一代，仍是 beta。生产环境此刻没有理由迁过去，但可以拿测试节点先跑，提前发现主题与插件的不兼容。
- Wings `v1.13.5`（2026-11-11）比 Panel 还新，说明两侧独立发版，别假设"面板升了节点就同步了"。

容器化把两件事交给你自己负责：**卷映射**（世界与插件配置必须在宿主机上，容器重建不丢）和**内存上限**（容器 limit 要大于 JVM 堆，留 1–1.5GB 给堆外内存；否则进程是被内核杀的，不抛异常，日志断在正常输出上）。

## 不同规模的建议

**10 人以内**：单 Paper + LuckPerms（文件存储）+ CoreProtect + 定时快照。不要上代理，多一层就多一个故障点。

**20–100 人**：Velocity + 2–4 个子服，LuckPerms 指向共享库，CoreProtect 单独库并设保留期，备份走快照 + 日备。

**100 人以上或多节点**：Pterodactyl 一类面板统一编排，Wings 管容器，代理单独一台机器，权限与审计库独立部署并做主从，备份异地。

## 变更管理与回滚演练

线上事故里有一半不是"选择错了"，而是"改的时候没有回退路径"。三个习惯能挡掉大部分：

**升级前先做还原点，且要包含 ⟦plugins⟧ 目录。** 很多人只备世界，结果回滚时发现插件配置已经被新版本改写过——旧 jar 配新配置，照样起不来。

**回滚点要写成文件名，不是"上一版"。** 把 ⟦paper-26.2-xxx.jar⟧ 这种完整文件名记进变更记录。出事时最贵的是找文件的那十分钟。

**升级顺序固定为代理 → 子服 → 插件**，每步做完立刻验证：能登录、能跨服、能执行一条权限命令。三步一次性做完再验证，出问题时无法定位是哪一层。

**每季度演练一次恢复。** 把最新备份解到临时实例、换个端口起、走进去。演练的价值不在于"能不能起来"，而在于暴露那些平时看不见的依赖：数据库连接串写死了内网 IP、某个插件密钥只在旧机器上、世界目录之外还有一份被遗忘的配置。

## 常见坑

1. **转发模式混用**。modern 与 legacy 同时开，部分玩家 UUID 错乱、皮肤丢失。
2. **子服可被直连**。只用 legacy 又不做网络隔离，等于把伪造入口敞开。
3. **LuckPerms 各服各库**。权限"有时生效有时不生效"，其实读了两份数据。
4. **直接打包运行中的世界**。备份"成功"，恢复后区块错乱。
5. **CoreProtect 日志不设保留**。半年后磁盘满，先崩的是数据库。
6. **Panel 与 Wings 混着升级**。跨度大时 API 不匹配，节点显示离线。
7. **容器内存 limit 等于 `-Xmx`**。进程被 OOMKiller 杀，日志无异常。
8. **脚本还在用 `api.papermc.io/v2`**。接口已 sunset，脚本静默下到旧包。
