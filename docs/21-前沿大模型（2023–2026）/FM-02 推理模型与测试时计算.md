# FM-02 推理模型与测试时计算

**一句话结论**：2026 年的「推理」不再是一类模型的名字，而是一次请求上的参数——模型档位、`reasoning effort`、速度模式三轴相互正交，测试时计算从「要不要想」变成「花多少想、在哪一维花」。真正的分野也换了位置：不是「谁更会推理」，而是「谁能把 effort 与成本的关系画成一条可用曲线」。

## 一、三年三段：推理是怎么从模型变成参数的

| 阶段 | 推理的形态 | 用户怎么控制 | 典型代价 |
| --- | --- | --- | --- |
| 2023-11 至 2024 | 独立模型线（chat 与 reasoning 分开命名） | 选模型 | 换模型就得换 prompt 与评测 |
| 2025 | 思考预算内建，长 CoT 成为训练目标 | 单一开关或预算参数 | 想得越久越贵，但只有一档 |
| 2026 | 同一家族多档 effort，且可中途切换 | 档位 + 速度模式 + 并行编排 | 档位选错的成本超过换厂商 |

这条演进的技术含义是：**测试时计算（test-time compute）从「架构选择」变成了「调度决策」**。2024 年你要决定「用不用 o1 那一类模型」；2026 年同一族模型内就能选 low 到 max，且官方明确支持在对话中途改档位。

## 二、四家的控制面长什么样

| 厂商 | 控制项 | 档位 | 默认 | 一手来源 |
| --- | --- | --- | --- | --- |
| OpenAI | `reasoning effort` | Low / Medium / High / Extra high（Max） | Codex 从该模型默认值起步 | openai.com/index/practical-guide-building-gpt-6 |
| Anthropic | effort | Low / Med / High / Xhigh / Max | Claude 应用与 Claude Code 默认 Medium | anthropic.com/claude-fable-and-mythos-5-2 |
| DeepSeek | thinking / non-thinking | 二态开关 | thinking 为默认 | api-docs.deepseek.com/quick_start/pricing |
| Kimi K3 | reasoning-effort levels | 多档（报告未逐档列明） | 未核实 | arXiv:2607.24653 |
| Google | 未取得 | — | — | 本轮缺口 |

OpenAI 在 10 月 2 日的 GPT-6 模型指南里给出了四档的语义，这是目前唯一把「档位 = 任务类型」写清楚的官方文档：

- **Low**：例行动作，例如抽取事实、做小改动；
- **Medium**：需要判断的工作，例如规划一个功能、比较多个选项；
- **High**：困难调试、更深分析、仔细复核；
- **Extra high / Max**：官方原话是「在 High 不够时才测，并且只有收益能抵掉增加的时间与成本才保留」。

指南里还有两个容易被忽略的工程事实：**（1）可以在对话中途改 `reasoning effort` 而不破坏缓存**；**（2）速度与思考是两个独立维度**——Fast mode 用更高的每 token 价格换更快更稳定的响应，Ultrafast 只对 GPT-6 Astra 开放，官方写明它 accelerates token generation independently of reasoning effort。也就是说「想多久」和「吐多快」是两根不同的旋钮，不是一根。

Anthropic 这一侧的证据来自发布页的图表坐标轴与正文：Fable 5.2 的 accuracy-cost 曲线横轴是 Low / Med / High / Xhigh / Max 五档，正文明确 Medium 是 Claude 应用与 Claude Code 的默认档。Kimi K3 的技术报告只写了 multiple reasoning-effort levels，没有逐档给出预算，所以它在本稿里只能算「存在多档」，不能算「可对照」。

## 三、分数-成本曲线：测试时计算的边际收益在哪衰减

2026 年最有价值的一手材料不是单点分数，而是把 effort 当自变量画出来的曲线。Anthropic 在 5.2 发布页给出的几组对照，可以被读成一条「先陡后平」的收益曲线：

| 设定 | 结果 | 对照基准 | 成本关系 |
| --- | --- | --- | --- |
| FrontierCode 2.0，Fable 5.2 @ High | 45.3% | ≈ Opus 5.5 @ Max 的 45.5% | 每任务成本约一半 |
| FrontierCode 2.0，Fable 5.2 @ Xhigh | 49.1% | 已发布模型中最高 | 再往上一档才有 +3.8 点 |
| WANDR，Fable 5.2 @ Medium | 追平 Opus 5.5 的最高分 | Opus 5.5 | 成本约 40% |
| Humanity’s Last Exam（带工具），Fable 5.2 @ Low | 追平 Opus 5.5 的最高分 | Opus 5.5 | 成本不到 1/10 |
| BenchCAD 2.1（带工具），Fable 5.2 @ Max | 83.5 | Opus 5.5 的 65.3、Fable 5.1 的 44.4 | 未公布成本 |

这张表说明三件事。**第一，低 effort 的性价比在「够得着」的任务上是碾压性的**：HLE 上 Fable 5.2 用 Low 就打平了 Opus 5.5 的最好成绩，代价不到十分之一。**第二，高 effort 只在接近天花板时才有增量**：FrontierCode 从 High 的 45.3% 到 Xhigh 的 49.1%，多出来的 3.8 点要靠跨一个档位来买。还有一条常被忽略的观察：在同一张表里，Fable 5.2 在 Xhigh 档的 49.1% 与 GPT-6 Astra 的 42.8% 之间差的 6.3 点，而两家的每百万 token 价格只差约 25%（8/40 对 10/50），说明「档位」这一维在 2026 年已经能抵得上半个代际的差距。**第三，同一家族内换 effort 的收益可能大于换家族**：Fable 5.2 相对 Fable 5.1 在 FrontierCode 上是 49.1% 对 32.4%，接近 +17 点，而跨到 Opus 5.5 只差 3.6 点。

## 四、第二条扩展轴：宽度而不是深度

2026 年另一个明确的转向是**并行扩展**，它和「想更久」是两种不同的测试时计算。

- **OpenAI** 在 GPT-5.6 引入 `ultra` 档，官方描述是 coordinating multiple agents across parallel workstreams（跨并行工作流协调多个 agent），属于「用更多 agent 换更快完成」；GPT-6 指南则把 steering、async tools、delegation 列为处理长任务的三种手段。
- **Kimi** 在 K2.5 里提出 Agent Swarm，自我导向地把复杂任务分解成异构子问题并发执行，官方报告称延迟相比单 agent 基线最多降低到 1/4.5（4.5×）。

工程上这两条轴的成本结构完全不同：**深度扩展的账单随输出 token 线性增长，宽度扩展的账单随并发数增长但受速率限制约束**。DeepSeek 的并发上限（V4.1-Flash 2500、V4-Pro 500）就是个硬边界——宽度扩展在低并发配额上会先撞墙。

## 五、effort 与缓存的耦合，是省钱的关键

官方指南里那句「中途改 effort 不破坏缓存」看似小细节，实际决定了长会话的最优策略。把稳定前缀（系统指令、仓库说明、参考资料）放在前面、把变化的任务细节与 effort 档位放在后面，就能同时拿到两件事：缓存命中的折扣 + 按任务难度调档。

| 模型 | 缓存输入价 | 未缓存输入价 | 倍数 |
| --- | --- | --- | --- |
| GPT-6 Astra | $1.00 | $10.00 | 10× |
| GPT-6.1 Sol | $0.10 | $2.00 | 20× |
| DeepSeek-V4-Pro | $0.022（谷） | $0.66（谷） | 30× |
| Claude Opus 5.5 | $0.20 | $4.00 | 20× |

反过来说，**在最贵的档位上把 effort 拉满、又让缓存全部失效，是 2026 年最容易踩的账单事故**：Astra 输出价 $50 每百万 token，一次 5,000 token 的 max effort 输出就是 $0.25，还没算思考 token。

## 六、effort 为什么「可以调」：训练侧的线索

很多人把 effort 当成纯解码技巧（想久一点、采样多一点），但 2026 年的公开材料显示它是**后训练阶段就训练出来的能力**。Kimi K3 的技术报告在描述后训练时写得很直白：强化学习覆盖通用、agentic、coding 三个领域，并且覆盖 multiple reasoning-effort levels，由此获得组合泛化与稳健的长程执行。也就是说，多档 effort 是训练中显式优化的目标，不是推理时临时设法。

这也解释了曲线为什么是「先陡后平」而不是线性：模型被训练成在不同预算档位下采用不同策略——低档位学的是「抓住要点、少走弯路」，高档位学的是「多路径试错、自我校验」。低档位在容易任务上的高性价比来自训练时对捷径的学习，而不是「少想几步」。

## 七、怎么选档：一张决策表

| 任务形态 | 建议 effort | 建议模型档 | 理由 |
| --- | --- | --- | --- |
| 抽取、改写、格式转换 | Low | Luna / Haiku / Flash | 任务可判定，加档位不改变正确率 |
| 单文件修 bug、写测试 | Medium | Sol / Sonnet / Opus（按难度） | 需要判断但反馈闭环短 |
| 跨仓库重构、难复现的并发问题 | High | Astra / Fable 或 Mythos | 反馈稀疏，需要自校验与多路径 |
| 数学证明、科研假设筛选 | Max（先做小样本） | 能力顶 + 带工具 | 只有接近天花板时高 effort 才有增量 |
| 大规模批处理、实时客服 | Low 或 non-thinking | 最便宜档 | 延迟与成本是主约束 |
| 长会话 agent | 按步调档 | 中档为主 | 改 effort 不破缓存，可在难步临时升档 |

## 八、复现清单：把 effort 钉死

要让别人能复现一次 2026 年的评测，至少记录五项：**(1)** 模型名与版本号（`deepseek-flash` 背后是 DeepSeek-V4.1-Flash-1017 这类映射必须写明）；**(2)** 实际 effort 档位；**(3)** 速度模式（标准 / fast / ultrafast）；**(4)** 是否触发护栏路由（Fable 5 时代会降级到 Opus 4.8 回答）；**(5)** 工具集合与最大轮次。缺少任何一项，同一组分数在不同时间跑出来就可能是两个数。
## 九、实际影响

**1. 榜单必须标注 effort 才有可比性。** Anthropic 的对照表注明 highest-available effort，OpenAI 在 GPT-5.6 页面同时给「max reasoning」与「medium reasoning」两组数字（后者用约 1/4 的估计成本把与 Fable 5 的差距从 13.1 点缩到 11.4 点）。不标 effort 的分数无法复现。

**2. 默认档选错的代价可能超过选错模型。** 从 Luna 换到 Astra 是 100 倍单价，从 Medium 换到 Max 在长任务上同样能放大数倍；两者相乘就是数量级差异。

**3. 选型顺序应该反过来。** 先判断「任务是否可判定、是否需要工具」→ 再定 effort → 最后定模型档位。2024 年的顺序（先挑最强模型）在 2026 年是最贵的做法。

**4. 评测要记录三件事**：实际 effort、速度模式（标准 / fast / ultrafast 价格不同）、以及实际回答模型（护栏触发时可能不是你以为的那个模型）。

## 十、常见坑与局限

- **跨厂商同名档位不可比**：Medium 在 OpenAI 是「需要判断的工作」，在 Anthropic 是「Claude 应用默认」，两家的 token 预算都没公开过。
- **把 Max 当默认**：官方自己写「Extra high 先测，收益不足就不要」，把它设成默认既不省钱也不一定更稳。
- **忽略 fast mode 的加价**：Claude Fable 5.2 标准价 $8 / $40，fast mode 是 $16 / $80，正好 2 倍；提速 2.5 倍，单 token 性价比略升，但不是免费。
- **把「想得久」等同于「并行 agent」**：前者是深度扩展，后者是宽度扩展，账单结构和失败模式都不同。
- **思考 token 的计费口径**：多数 API 把思考 token 计入输出，但本轮没有逐家核实 2026 年的细则，做预算时应按最坏情况（全按输出价）估。
- **本稿的结构性局限**：Google 侧的 thinking/effort 控制面完全没取到；Kimi K3 只确认「有多档」而没有档位细节；所有厂商的 effort→token 预算映射都未公开。
