# FM-03 开源权重模型 2026（DeepSeek-V4-Pro/V4.1-Flash、Qwen3.x、Llama、Kimi、GLM、MiniMax）

**一句话结论**：2026 年开源权重的天花板已经推到 **2.8T 参数级 MoE**（Kimi K3，104B 激活、1M 上下文、原生视觉），但「开放」其实是三个可以分开卖的词——权重、论文、训练配方。这一年真正的新格局是：DeepSeek 把「开放权重」与「极低价 API + 峰谷分时」绑成商业策略，Kimi 用超大 MoE 抢能力天花板，GLM 用架构降本抢性价比，而 Qwen / Llama / MiniMax 在本次一手取证中只拿到部分证据，不能与前四家并列断言。

## 二、DeepSeek：用「家族 + 分时」定价开源叙事

DeepSeek 是这一年把「开源权重」与「API 生意」结合得最紧的一家。官方 API 端只暴露两个模型名：`deepseek-flash` 实际由 **DeepSeek-V4.1-Flash-1017** 提供服务，`deepseek-v4-pro` 背后是 **DeepSeek-V4-Pro-0813**。这里有两个值得写进工程笔记的机制：

**（1）模型名是稳定接口，版本号藏在背后。** 旧名 `deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 仍被接受，但对应模型已退役，请求会落到 V4.1-Flash-1017 并按 Flash 价计费。这意味着「我用的还是老模型」是一种幻觉——账单和输出都会静默变新。

**（2）价格按时段分档。** 峰时为 UTC 01:00–04:00 与 06:00–10:00（周一至周五，中国法定节假日除外），谷时价正好是峰时的一半。把批量任务挪到谷时，等于直接打五折，比换模型更划算。

| 模型（版本） | 上下文 / 输出 | 缓存命中 | 缓存未命中（谷 / 峰） | 输出（谷 / 峰） | 并发上限 |
| --- | --- | --- | --- | --- | --- |
| `deepseek-flash`（V4.1-Flash-1017） | 1M / 384K | $0.003 / $0.006 | $0.15 / $0.30 | $0.60 / $1.20 | 2500 |
| `deepseek-v4-pro`（V4-Pro-0813） | 1M / 384K | $0.022 / $0.044 | $0.66 / $1.32 | $1.98 / $3.96 | 500 |

两者都是 thinking 模式为默认、支持 JSON 输出与工具调用；差异在视觉（Flash 支持、Pro 不支持）与并发（5 倍）。

## 三、Kimi：把开源上限推到 2.8T

Kimi K3 是这一年开源侧最硬的工程声明：2.8T 总参数、104B 激活的 MoE，原生视觉，1M token 上下文。三个架构名词值得记住：

- **Kimi Delta Attention（KDA）**：改进跨序列长度的信息流；后续还有专门分析其表达力的论文（arXiv:2609.24797）。
- **Attention Residuals**：改善跨模型深度的信息流。
- **Stable LatentMoE**：每个 token 激活 896 个路由专家中的 16 个。

官方称相比 Kimi K2 在整体扩展效率上提升约 **2.5 倍**，并明确写了「发布完整 Kimi K3 权重」。更值得注意的是它的自我定位：报告直接承认整体仍落后 Claude Fable 5 与 GPT-5.6 Sol，但稳定超过评测中的其他开源与闭源模型。**这是 2026 年开源叙事的诚实版本——不再宣称追平，而是宣称「稳定第二梯队且可自托管」。**

上一代 Kimi K2.5（2026-02-02）走的是另一条路：开源多模态 agentic 模型 + Agent Swarm，把复杂任务分解成异构子问题并发执行，官方称延迟相比单 agent 基线最多降到 1/4.5。K3 与 K2.5 的分工也清楚：K2.5 抢「多 agent 编排」，K3 抢「单模型能力上限」。

## 四、GLM-5：用架构换成本

GLM-5 的技术报告标题就是它的立场——from Vibe Coding to Agentic Engineering（从凭感觉写代码到 agentic 工程）。三个技术点：

1. **DSA**：官方称显著降低训练与推理成本，同时维持长上下文保真度；
2. **异步 RL 基础设施**：把生成与训练解耦，大幅提升后训练效率；
3. **异步 agent RL 算法**：让模型能从复杂长程交互里更有效地学习。

报告称其在主要开放基准上达到 SOTA，并在真实编码任务（端到端软件工程）上超过此前基线，代码与模型公开在 `github.com/zai-org/GLM-5`。这条路线和 Kimi 正好相反：Kimi 用更大参数换能力，GLM 用更省的注意力与异步训练换同等能力的成本。

## 五、Qwen / Llama / MiniMax：证据不足的部分必须说清楚

本稿对这三家只做**证据陈述**，不做能力断言：

- **Qwen**：arXiv 上能看到 Qwen3.5 家族确实存在——有 0.8B、4B、27B 变体的第三方研究直接引用，也有官方的《Qwen3.5-Omni Technical Report》（arXiv:2604.15804）。但 qwen.ai 博客为纯 JS 渲染，本轮没有取到官方发布页，因此权重许可、参数量、上下文长度全部空缺。
- **Llama**：在本轮的 arXiv 标题检索中没有出现任何 Llama 的 2026 代际技术报告（命中项都是围绕 Llama 3 / Llama-3 的推理优化与微调论文），llama.com 与相关官方域名在本机网络不可达。**结论只能是「未获取」，不能是「没有发布」。**
- **MiniMax**：arXiv 标题检索 `ti:"MiniMax-M"` 无命中（结果被数学意义上的 minimax 淹没），官方域名不在本次可核验来源清单内。同样只能标记为缺口。

## 六、「开源」的三种开放度

把上面几家的证据摆在一起，2026 年的「开源」至少有三个可以分离的维度：

| 模型 | 权重是否公开 | 是否有技术报告 | 训练配方/数据 | 备注 |
| --- | --- | --- | --- | --- |
| Kimi K3 | 是（报告明写 release the full weights） | 是（arXiv:2607.24653） | 未公开 | 2.8T / 104B 激活 |
| Kimi K2.5 | 是（released checkpoint） | 是（arXiv:2602.02276） | 未公开 | 多模态 + Agent Swarm |
| GLM-5 | 是（代码与模型在 GitHub 公开） | 是（arXiv:2602.15763） | 未公开 | DSA + 异步 RL |
| DeepSeek-V4 系 | **一手页未声明** | 未检索到官方技术报告 | 未公开 | API 端名为 `deepseek-v4-pro` / `deepseek-flash` |
| Qwen3.5 | 未核实 | 仅 Omni 报告可见 | 未公开 | 官方博客未取到 |
| Llama / MiniMax | 未核实 | 未检索到 | 未公开 | 本轮无一手数据 |

这里有个反直觉的点：**DeepSeek 是最积极谈「开放」的一家，但它的 API 变更日志并不谈权重**。要确认 V4 系权重是否放出，必须去看模型托管页或仓库，而这两类站点不在本轮允许的一手来源内。所以本稿对 DeepSeek 的「开源权重」只能写「未在一手页声明」，不能替它背书。

## 七、实际影响

**1. 自建与调用的分水岭变了。** 2025 年的算法是「参数量 × 显存 / 云价」；2026 年要加上两件事：一是 API 侧的**峰谷差价 2 倍**与**缓存命中差 30 倍**（DeepSeek V4-Pro 缓存命中 $0.022 对未命中 $0.66），二是**并发上限**（2500 vs 500）——自建的真正对手不是单价，而是配额。

**2. 「开源」必须拆成三个问题问。** 权重能否下载？技术报告是否披露架构？训练数据与配方是否公开？Kimi K3 满足前两项、不满足第三项；DeepSeek V4 在前两项上本稿都没拿到证据。把这三个问题混成一句「开源了」，是这一年最常见的表述失真。

**3. 评测口径已经分家。** DeepSeek 用自家 Harness minimal 模式测；Kimi 用自己的评测套件；GLM 用自己的开放基准。2026 年的「开源模型横比」如果不复现对方的 harness，分数没有可比性。

**4. 长上下文是新的竞争面。** Kimi K3 与 DeepSeek V4 都到 1M，DeepSeek 还把最大输出开到 384K。这直接把「上下文管理」变成了应用层问题：同样的 1M 窗口，缓存命中与不命中的成本差 30 倍。

**5. 自建的隐性成本在「长上下文 × MoE」。** 1M 上下文窗口听起来是能力，落到部署上是 KV 缓存与显存带宽的问题：Kimi K3 是 104B 激活的 MoE，DeepSeek V4 系把最大输出开到 384K。真正决定自建可行性的不是参数量，而是「你的平均并发 × 平均上下文长度」能不能装进一张卡组，以及填满 1M 窗口时的缓存开销谁买单。
## 八、常见坑与局限

- **把 API 模型名当开源版本号**：`deepseek-flash` 不是模型名，是接口名，背后会换版本（现为 V4.1-Flash-1017）。
- **以为退役模型会立刻报错**：`deepseek-v4-flash`、`deepseek-v4-flash-vision-exp` 仍被接受，但请求被静默导向新模型并计费。
- **把「开源」等同于「可商用」**：本轮没有取到任何一家的许可证原文，商用前必须自行核实。
- **忽略峰谷与缓存**：DeepSeek 的谷时价是峰时的一半，缓存命中价是未命中的 1/30 到 1/50，这两项对账单的影响大于模型选择。
- **拿厂商自报分数横比**：DeepSeek 的分数绑定 `top_p=0.95`、`temperature=1.0`、max effort 与自家 harness；换环境就不是同一件事。
- **本稿的结构性局限**：Qwen、Llama、MiniMax 三家都没有取到官方发布页，DeepSeek 的权重开放性没有一手证据，Kimi K3 的许可证细节未核实。
